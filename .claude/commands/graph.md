# /graph — карта связей проекта

Полное описание инструмента и, главное, **границы доверия** — в
`.claude/skills/graphify/SKILL.md`. Прочитай его, если ещё не читал в этой
сессии: без раздела «Границы доверия» граф легко прочитать неправильно.

## Шаг 1. Убедиться, что инструмент есть

Контейнер сессии эфемерный, установка живёт только внутри сессии:

```bash
export PATH="$HOME/.local/bin:$PATH"
command -v graphify >/dev/null || uv tool install graphifyy
```

## Шаг 2. Собрать граф

```bash
graphify extract . --code-only
```

~10 секунд, результат в `graphify-out/` (в `.gitignore`, в коммит не идёт).
Запуск повторно — инкрементальный, только изменённые файлы. Пересобирай после
своих правок, иначе будешь отвечать по устаревшей карте.

## Шаг 3. Ориентировка

Без аргумента — общая карта:

```bash
graphify god-nodes --top 12
```

С аргументом `$ARGUMENTS` — по конкретному месту:

```bash
graphify explain  "$ARGUMENTS"   # все связи: кто зовёт, кого зовёт, с file:line
graphify affected "$ARGUMENTS"   # blast radius: кого заденет правка
```

## Шаг 4. Что доложить

Коротко и по делу:

- к какому кластеру относится место задачи и какие несущие узлы рядом;
- если был аргумент — список задетых файлов (это и есть область регрессии,
  её же проверяем перед «готово»);
- что из найденного уже решает задачу и должно быть переиспользовано
  (Hard rule #6) — эта строка идёт в `Reuse audit:`.

## Чего этой командой делать НЕЛЬЗЯ

Объявлять код мёртвым. Граф не видит вызовы по строке (`invokeFn('…')`,
`.rpc('…')`), JSX внутри одного файла, CSS-классы и i18n-ключи — у него по
нашему репозиторию 199 ложных «сирот» в `src/**` и 43 из 45 «мёртвых»
edge-функций, которые на самом деле живые. Граф даёт **кандидата**;
подтверждение — ручной проход по `src/**`, `supabase/functions/**`,
`supabase/migrations/**`, `locales/**`, `*.css` и воркфлоу n8n.
