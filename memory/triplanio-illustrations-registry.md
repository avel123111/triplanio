# Иллюстрации и маскот Боно в приложении (TRIP-532)

## Как это устроено сейчас
- **Реестр** `src/design/illustrations.js`: одно место с путём и собственными размерами каждой картинки. Файлы — `public/images/<что-где>.webp` (WebP с альфой, 2× плотность: плитки 384², герой 336×600). Имя по смыслу (`create-ai`), не по типу: в папке живут и маскот, и предметные сцены, и их комбинации (в `create-ai` Боно запечён как аватар ответа).
- **Примитив** `<Illustration name="…" />` (`src/design/Illustration.jsx`, экспорт из `index`): `<img width height alt="" decoding="async">`, без `loading="lazy"` (все потребители над сгибом) и без `className`/`style`. **Своего класса нет намеренно** — размер, рамку и подложку задаёт владелец (`.choice-card__vis img`, `.eroute__fig img`), как у иконки; иначе у картинки появился бы второй голос в раскладке и вызыватели чинили бы его инлайном. Ноль новых namespace.
- **Токены размеров** `--art-tile: 96px` · `--art-state: 200px` · `--art-hero: 300px` (`:root`, апрув Pavel): владелец берёт ступень, примитив размера не знает. Пара способов создания — один элемент `CreateChoicePair({ col, onManual, onAi })` в `CreateTripProvider.jsx`, диалог и `/trips` рисуют её через него.
- **Тест** `src/design/illustrations.test.js` пинит три молчаливых дрейфа: файл существует; `w/h` записи = размеру файла из заголовка WebP; каждый литерал `name="…"` в `src/**` есть в реестре (неизвестное имя рендерит `null` без предупреждения).
- **ChoiceCard** (`CreateTripProvider.jsx`): проп `art` → плитка-картина `.choice-card__vis` (квадрат 96 на всех ширинах) вместо плитки-иконки; `col` → колонка для пары «две рядом» в диалоге на канон-сетке `.grid grid--split grid--g6`: у неё своя ступень «один столбец ≤880», и карточка на той же ступени возвращается к строке — про сетку она не знает.
- **EmptyState** получил проп `art` (картина из реестра вместо плитки-иконки, `icon` — фолбэк, размер задаёт `.empty-state__art img`). Первый потребитель — «Путешествие создано» (`ManualPlanner`, `trip-created`). План Pavel: у пустых состояний по экранам свои картины + одна дефолтная — всё через этот проп, без второго примитива.
- **Экран успеха в теле панели шелла — по центру по вертикали.** Правило у ПОВЕРХНОСТИ, а не у экрана: `.mapshell__body .empty-state, .peek-sheet__body .empty-state { flex: 1 }` (как `.dlg .empty-state`/`.sheet .empty-state`) — `.empty-state` сам центрирует содержимое, ему нужен только рост в флекс-колонке тела шага `.flow-lp-b` (`min-height: 100%`). Вариант `.flow-lp-b > .empty-state` пол 2o считает «экран дотянулся в примитив» (+1), канон-в-канон — нет. На телефоне визард на успехе поднимает шит на верхний детент (`setDetent(SHEET_TOP)`, индекс 2 в трио `[0.15, 0.68, 1]`): на полу-детенте картина 200 + текст + две кнопки не влезали (скролл 100px, кнопки за краем экрана 739). Замер на стенде: десктоп 14/14 сверху-снизу, телефон скролл 0.
- **Пустой экран `/trips`** (`EmptyRoute`): `.eroute` — grid «текст+карточки | герой», рельса маршрута снята целиком. Герой `bono-ready` в `.eroute__fig`, на ≤640 над текстом по центру. **`/trips` на десктопе во всю ширину (~1600px)** — лента-герой: слева ОДИН грид-элемент `.eroute__body` (заголовок, подзаголовок, пара карточек **рядом** строками), справа Боно 300px вровень с блоком, группа по центру с потолком 780px. Отвергнуто: карточки друг под другом (пункты меню, герой в углу) и карточки колонками с плитками 330px (иллюстрации съедают текст). Блок обязан быть одним элементом сетки, иначе грид раздаёт высоту героя строкам текста. Орбы-градиенты фона и стрелка `→` в карточках сняты (Pavel по Vercel-превью: карточки на метр, герой у правого края, орбы пятнами на тёмной).

## Решения Pavel (2026-09-07)
- Маскот **вне** карточек выбора: два Боно рядом читались дублями, Боно-аватар в шапке диалога «ни к чему». Один герой, карточки — пара равных.
- Плитка 1:1 под картинку 1:1 (несовпадение пропорций читалось как «обрезано»); диалог — две рядом; надпись «Начать с Triplanio» без изменений.
- Картинки универсальные для обеих тем: насыщенные заливки, без белых поверхностей, без теней (тень на прозрачном PNG = серый ореол на тёмном).
- Поза героя без направления (сидит на чемодане, смотрит на зрителя): на десктопе он справа от карточек, на телефоне над ними, жест «в сторону» указывал бы в пустоту.

## Ловушки
- Генератор может **нарисовать «шахматку» в пикселях** вместо альфы (так пришёл первый `bono-ready`): PNG без альфа-канала. Лечение — перегенерить, у того же генератора следующий заход отдал настоящую альфу; временная выбивка по цвету (эрозия маски 2px + снятие светлой подложки) оставляет след на тёмной теме. Проверять `ct` заголовка PNG, не глазами.
- Картинка со своей запечённой тенью/фоном на тёмной теме = стикер. Правило: фон и тень отдаёт поверхность-владелец.
- Плитка и картинка должны быть одной пропорции: квадрат в 124×88 «облизывал» высоту и стоял с полями.
- **Ступень токена не уменьшать под один экран.** `@media (max-width:640px){:root{--art-state:140px}}` (по образцу `--ctl-h`) чинит шит, но `--art-state` читает и герой `/trips` на телефоне — Боно 336×600 в 140 по высоте стал 78 в ширину, мелкий под заголовком (замер на стенде). Ступень `--art-tile` (96) в шите превращает сцену в иконку. Если поверхности нужен другой размер — менять поверхность (детент, отступы), а не шкалу.
- 2p считает составное правило и по ПЕРВОМУ подлежащему: `.peek-sheet__body .empty-state { flex:1 }` печатает ключ `.peek-sheet__body flex` (у тела `flex:none`), маркер нужен на оба ключа; `.mapshell__body` не печатает — у него уже `flex:1`.
- Исходники PNG и промпты — в `Triplanio design new/`, не в репо.
