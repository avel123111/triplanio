Все карточно-панельные поверхности имеют ЕДИНЫЙ источник вида - один групповой
селектор в `src/design/app.css`. ★TRIP-326 схлопнул две роли в ОДНУ плоскую: ни
тени, ни backdrop-blur больше нет, групповой селектор задаёт только
`border-radius: var(--r-xl)`. `.surface-glass` и `.surface-panel` остались
АЛИАСАМИ ради совместимости разметки - оба дают одинаковый результат, выбирать
между ними больше нечего. Токенов `--surface-card`, `--surface-card-border`,
`--shadow-glass`, `--glass-blur` в репо НЕТ (удалены вместе с ролями; описание
их значений ниже по файлу - история TRIP-189, не текущее состояние).

В группе (все дают один и тот же вид): `.surface-glass`/`.surface-panel`,
`.statbar` (полоса статистики - на `/trips` И на обзоре трипа), `.wmini`,
`.nextcard`, `.nonext`, `.tr`, `.tl3-card`, `.card`, `.wdg`, `.panel`,
`.summary`, `.invite`, `.acc`, `.acct-hero`, `.chat-reply__card`, `.pl-lastcard`.
`.docfield` - в DocumentsField.css, на тех же токенах напрямую.

★Следствие для новых экранов: вопрос «какая роль на этом экране» больше не
возникает и вешать скин-класс в точке использования НЕ надо - достаточно, чтобы
класс примитива стоял в групповом селекторе. Исторический принцип «на одном
экране все поверхности одной роли» (из-за него Pavel видел «больше 2 стилей»:
стеклянная statbar рядом с плоским виджетом на /trips) выполняется теперь
автоматически.

Правила поддержки: примитивы НЕ дублируют скин - подключаются к роли через
групповой селектор, а в своём блоке держат только внутреннюю раскладку
(падинги/хедеры/overflow). Новую поверхность вешать на `.surface-glass` или
`.surface-panel`, не переопределять фон/бордер/радиус руками. Глобальные
`--surface`/`--line` НЕ трогали - инпуты/меню/чипы/строки остались как были
(иначе «остеклился» бы весь UI в тёмной теме). Карточки-постеры трипов `.tc`
(фон-картинка + скрим) вне ролей: выровнен только радиус на `--r-xl`, тень/фон
свои. Прочие вне ролей (осознанно разные примитивы): `.limitcard` (брендовый
алерт лимита), `.tl3-card` (карточки эвентов таймлайна - защищены отдельным
фидбэком [[feedback-redesign-means-from-scratch]]), строки-списки (`.bookrow`,
`.bgt-exrow`, `.acct-chan`…), вложенные recessed/inset-блоки на `--surface-3`
(`.addr`/`.notes`/`.doc-row`…), контролы (инпуты/кнопки/сегменты) и
оверлеи (`.toast`/`.sheet`/`.chat-mention`/диалоги). Имена `.tp-glass-card`/`.tp-panel`/`--card-border`/`applyLook()` из тикета -
из HTML-прототипа `Triplanio.dc.html`, в реальном React/Vite-репо их нет.
★Тёмная лестница поверхностей (аудит 2026-07-05): реально рендерятся РОВНО 4
серых - `--bg` #0c0e1c (страница), `--surface` #1f212f (карточки/панели/диалоги
`.dlg`/`.lp`/строки/инпуты), `--surface-2` #2a2937 (чипы/hover/футеры/треки),
`--surface-3` #1b1a26 (inset/сайдбар). Дубли `--card`/`--secondary`/`--muted`/
`--accent` уже алиасят наши. Захардкоженного hex-дрейфа фонов нет (5 литералов -
все `#fff` в AI/цветных контекстах). Значения вроде #232331/#2d2e3c, которые
«ловит пипетка» на скрине, - это СМЕШАННЫЕ пиксели (бордер `--line` #33313f над
`--surface`, backdrop-blur скрима, сжатие), НЕ отдельные поверхности; проверять
через DevTools inspect (computed), не пипеткой по картинке. ★Мёртвый shadcn-слой
`--*-hsl` (`--popover-hsl`=#232331, `--secondary/muted/accent/input-hsl`) и
`--surface-elev`=#272636 удалены (Tailwind из проекта убран в TRIP-53 → 0
потребителей; засоряли токен-аудит, совпадали с «лишними» серыми).
Усиливает [[feedback-reuse-first-unification]] и [[triplanio-typography-canons]].
