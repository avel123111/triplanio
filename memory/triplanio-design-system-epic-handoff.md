## Зачем

**1341 CSS-класс в 282 семействах и 124 пространствах имён.** Один визуальный
объект — ряд, карточка, плитка, кнопка — объявлен заново десятки раз под
разными именами. Причина не «накопился беспорядок», а два механических порта:
каждый экран рисовался отдельным HTML-макетом со своим префиксом, а уход с
Tailwind заморозил каждый утилити-класс в литерал.

Цель: **на любой вопрос «где живёт этот стиль» есть один ответ, и он находится
за десять секунд.** Готово, когда одновременно: реестр примитивов закрыт ·
у каждого свойства один владелец · каждый канал возврата зоопарка закрыт гардом
с тестом · систему видно живьём на `/kit` · метрики удерживаются полом.
Не готово, если хоть один пункт держится на дисциплине, а не на механизме.

## Целевая архитектура

```
L0  ЗНАЧЕНИЯ     163 токена                      есть, состав не меняется
L1  РОЛИ         --ink/--muted/--brand, --ctl-h   есть
L2  ПРИМИТИВЫ    12 имён (9 есть, 3 новых)        Ф3
L3  КОМПОНЕНТЫ   17 визуальных                    Ф4
L4  ПАТТЕРНЫ     4 каркаса страниц                Ф5
L5  ЭКРАН        композиция и данные, ≤5 классов  Ф6
```

**Восемь законов.** 1) Один владелец на свойство; внешний отступ элементу не
принадлежит — его даёт `gap` родителя. 2) Значение течёт вниз по слоям, не
вбок; L5 не имеет права на литерал. 3) Специфичность не растёт: потомковый
селектор на примитиве может только переопределить переменную, которую примитив
читает. 4) Экран не изобретает объект. 5) Состояние — данные (`data-state` под
spread-хелпером по образцу `fieldState()`). 6) **PR унификации не меняет
общее.** 7) Решённое не переигрывается молча (`git log -S`). 8) **Число без
предиката в коде не существует; нет скрипта — пиши «не мерил».**

## Решения Р1–Р13

Р1 ярус ролей отступов отменён · Р2 брейкпоинты токенами не делаются,
`[640,880]` · Р3 кнопка = вариант из фиксированного набора, остальное
кликабельное `.lift` + фокус-кольцо · Р4 `.icon-btn` не новый · Р5 `.ic` на
удаление · Р6 новых имён три (`.lift`, `.head-row`, `.toolbar`) — **пересматривается**
под документ по кнопкам · Р7 тинт сводится к `--hl*` · Р8 токен = имя в `:root`,
понижение = нарушение · Р9 порядок каскада зафиксирован как сейчас, починка —
отдельный визуальный PR · Р10 витрина `/kit` под `!isProdHost` + `React.lazy` ·
Р11 счётчики объектов — первый PR подзадачи 04, до них 05/06 не начинаются ·
Р12 канон = семейство, чьи классы эмитит ДС; статус на семействе, храповик на
классах · Р13 визуальный гейт — четыре яруса, PNG-база отменена.

объявления реально достаются классу» считается статически, сразу по всем

их нет вообще.

снести дубль выглядят для него одинаково. Безопасной его делает только пара с

правила поменялся, значение — нет). Удаление живого пустого диффа не даёт

## Что НЕЛЬЗЯ

- **Прогоны по значениям** — ни по отступам, ни по цвету, ни по радиусам. Такой
  прогон уже сделал `.checkbox` под 11px круглым (радиокнопка на входе). Теперь
  ловит SPACING.
- **Менять общее под видом унификации** — перекрасить панели, переставить шкалу,
  сменить порядок каскада, удалить тон `ghost` (50 вызовов): отдельный PR + апрув.
- **Заводить имя или токен без апрува.** Новый префикс = новое пространство имён.
- **Копировать инлайн соседа** — повторяющийся инлайн у класса есть ошибка
  КЛАССА, лечится правилом на существующем классе.
- **Начинать 05/06 до счётчиков (Р11) и 04 до гейта (03).**
- **Ставить число в тикет без скрипта** (закон 8).
- **Верить чужому или прошлому скану** — перепроверять своим прогоном всегда.

## Процедура на каждый PR

`git fetch origin dev` → ветка от свежего `origin/dev` → прочитать TRIP-337 и
**смерженные PR соседей, а не их описания** → померить своим прогоном всё, на
что опираешься → один объект = один PR, новый примитив едет ВМЕСТЕ с миграцией
(иначе пол краснеет) → визуальный гейт зелёный, где проходит `cmp` — брать его →
гард с тестом и **таблицей мутаций в теле PR** → строка `Reuse audit:` →
закончить PR в `dev`, не голым пушем. Мержит Pavel; агент не мержит и не деплоит.

**Главный инвариант: ни один экран не должен выглядеть иначе.** Единственное
объявленное исключение — фаза 06 (семь крестиков в семи размерах нельзя
канонизировать, не сдвинув шесть), и там каждое движение предъявляется построчно.
