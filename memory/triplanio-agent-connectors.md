Чем агент (Cyrus = Claude Code в git-воркгри) реально дотягивается до внешних сервисов в сессии (выяснено 2026-06-24, TRIP-11). Значения токенов/ключей агенту НЕ видны и сюда НЕ пишутся — только канал и грабли.

- **Supabase — MCP-сервер** (`mcp__supabase__*`). Полный доступ: `list_projects`, `execute_sql`, `apply_migration`, `deploy_edge_function` + `list/get_edge_function`, `get_logs`, `get_advisors`, ветки, `generate_typescript_types`. Авторизация предсконфигурирована на стороне Cyrus (токен агенту не виден). Проекты и топология деплоя — см. [[triplanio-deploy-topology]] (prod `tizscxrpuopobgcxbekf`, dev `nydhzevdizkfaxdlikgc`, оба ACTIVE_HEALTHY, Postgres 17, org `ewufsvuiisddsiduyjwv`). Грабли: verify_jwt-капкан при batch-деплое — см. [[triplanio-deploy-verify-jwt]]. Деплой функций И миграций — теперь только через CI/CD (GitHub Actions, TRIP-68/73), агент сам НЕ катит (ни MCP `apply_migration`/`deploy_edge_function`, ни CLI) — см. [[feedback-no-manual-deploy-cicd-only]].

- **Vercel — НЕ MCP, а CLI.** `/usr/local/bin/vercel` (v54.16.0), уже залогинен: `vercel whoami` → `avel123111`, scope/team `avel123111-5277s-projects`, проект `triplanio_app`. Доступно: `vercel ls / inspect / logs / env ls / deploy / rollback`. Токен лежит в окружении, агенту значение не видно; отдельного Vercel-MCP в сессии НЕТ. Обычно ручной CLI-деплой не нужен — фронт (Vite) Vercel катит автоматически на push в ветку (см. [[triplanio-deploy-topology]]); CLI полезен для инспекции деплоев/логов/env.

- **Linear — MCP-сервер** (`mcp__linear__*`). Создание/правка задач (`save_issue`), комментарии, проекты, лейблы, статусы. Команда воркспейса — «Pavel» (UUID `6035454e-b654-4639-890c-eb0e26588f37`), префикс задач **TRIP**. При создании задачи `team` требует UUID, не имя.

- **Sentry — MCP-сервер** (`mcp__sentry__*`), подключён TRIP-20 (2026-06-24). Объявлен файлом **`.mcp.json` в корне репо** (`npx @sentry/mcp-server@latest --host=de.sentry.io`, токен из env `SENTRY_ACCESS_TOKEN`); секрет лежит в Railway (self-hosted runtime Cyrus), allow-list `mcp__sentry` включён в Cyrus webapp `/settings/tools` (вкладка Linear). Орга `triplanio` на **EU-регионе** (`de.sentry.io`) — `--host` обязателен, иначе сервер уходит на US и оргу не видит. Read-набор: `find_organizations/projects/teams`, `search_issues`, `search_events`, `get_sentry_resource`, `analyze_issue_with_seer` (Seer-разбор), + write `update_issue` (резолв/назначение). Авторизация = User Auth Token Pavel (read-скоупы), агенту значение не видно. Подробности самого мониторинга Sentry (фронт/edge/DSN) — [[triplanio-sentry-monitoring]]. OAuth-ремоут `mcp.sentry.dev` для облачного Cyrus НЕ поддерживается → только токен. Каталог `~/.cyrus/` (runtime-конфиг хоста) для агента закрыт наглухо — коннекторы добавляются через repo `.mcp.json` или дашборд `/integrations`, не правкой `~/.cyrus/mcp.json`.

- **n8n — MCP-сервер** (`mcp__n8n__*`), подключён TRIP-20 (2026-06-24, self-hosted инстанс Pavel). Объявлен в корневом **`.mcp.json`** (`npx -y n8n-mcp` — community-сервер czlonkowski, stdio-режим: `MCP_MODE=stdio`, `LOG_LEVEL=error`, `DISABLE_CONSOLE_OUTPUT=true`). Объём — **полное управление**: и база, и ключ через env-плейсхолдеры `N8N_API_URL` + `N8N_API_KEY` (URL НЕ в репо по решению Pavel). С API-ключом сервер даёт управление воркфлоу (list/get/create/update/execute) + справку/валидацию нод; без ключа — только справка. Чтобы заработало, нужно (вне репо, делает Pavel): (1) задать `N8N_API_URL`+`N8N_API_KEY` в Railway (runtime Cyrus), (2) включить `mcp__n8n` в allow-list Cyrus webapp `/settings/tools`, (3) рестарт сессии + смоук. PR #118 → dev (затем main). Значения секретов агенту не видны. Это исходящий канал АГЕНТА к n8n; рантайм-авторизация самих вызовов приложения в n8n (HS256-JWT) — отдельно, см. [[triplanio-n8n-jwt-auth]].

- **Notion — НЕ MCP, а REST через `curl`.** MCP-инструмента Notion в сессии НЕТ (ToolSearch ничего не отдаёт), НО в окружении есть `NOTION_TOKEN` (внутренняя интеграция, бот «Cyrus» в воркспейсе «Pavel's Notion») → пишем/читаем напрямую через `https://api.notion.com/v1/*` (заголовки `Authorization: Bearer $NOTION_TOKEN` + `Notion-Version: 2022-06-28`). Проверено TRIP-102 2026-06-26: `users/me`, `search`, `blocks/{id}/children`, `pages` (создание) работают. ВАЖНО: не заявлять «нет доступа к Notion» — есть, через REST. База знаний Triplanio = страница «Triplanio» (workspace-level) с разделами «1. Инфраструктура…» … «8. Дизайн-система». Парсинг ответов: `jq` (устарело: «в окружении НЕТ `python3`» — python3 **есть**, 3.11.15, плюс `uv` 0.8.17; см. [[triplanio-graphify-code-graph]]. Для JSON всё равно предпочитаем `jq`).
- **Playwright — MCP-сервер** (`mcp__playwright__*`), подключён TRIP-322 (2026-08-01). Объявлен в корневом **`.mcp.json`**, но запускается НЕ напрямую, а через обёртку **`scripts/agent/playwright-mcp.sh`** (см. ниже, почему без неё сервер мёртв после каждого передеплоя). Секретов в конфиге НЕТ. Даёт браузер как инструмент: 24 тула (`browser_navigate/snapshot/click/type/fill_form/take_screenshot/console_messages/network_requests/evaluate/wait_for/tabs/…`), работа через **accessibility-снимок** страницы, а не через картинку. Что важно знать:
  - **Версия пиньована намеренно.** Билд браузера прибит к версии Playwright внутри MCP (0.0.78 = Playwright 1.62.0-alpha); при `@latest` очередной релиз однажды потребует другой билд и сервер молча сломается посреди сессии. Обновление = отдельный PR + `install-browser --with-deps` в рантайме.
  - ⚠️⚠️ **Передеплой Cyrus ломает браузер, и персистентный том сам по себе НЕ спасает.** Бинарники браузеров на томе `/data/.cache/ms-playwright` действительно переживают всё, а вот **системные библиотеки хромиума (glib, nss, cups, pango, X11 — 21 штука) это apt-пакеты на оверлее контейнера** и стираются вместе с ним. Симптом: `chrome: error while loading shared libraries: libglib-2.0.so.0`. Проверено на живом передеплое 2026-08-01: `/opt/google/chrome` исчез, том цел, MCP всё равно упал. Лечение и есть обёртка: проверяет библиотеку-часового `/usr/lib/x86_64-linux-gnu/libglib-2.0.so.0` (на живом контейнере — мгновенный тест файла) и на свежем один раз зовёт `install-browser --with-deps chrome-for-testing`, которая ставит И браузер, И apt-зависимости. **Не убирать обёртку и не «упрощать» конфиг обратно в голый `npx`.**
  - **Браузер: `--browser chromium` = chrome-for-testing** на томе (`PLAYWRIGHT_BROWSERS_PATH=/data/.cache/ms-playwright`, путь закреплён явно, чтобы не зависеть от того, что `HOME=/data`). ⚠️ **Дефолт MCP — это канал `chrome`** (`/opt/google/chrome/chrome`), а НЕ бандл-хромиум: без явного `--browser chromium` первый же вызов падает `Chromium distribution 'chrome' is not found`. Настоящий Google Chrome (`install-browser chrome`, apt, ~431 МБ) живёт в `/opt` = оверлей → стирается всегда; chrome-for-testing на томе хотя бы не качается заново. Движок один и тот же Chromium 151, отличия реального Chrome (кодеки H.264/AAC, Widevine) нам не нужны. `--no-sandbox` НЕ нужен — проверено, headless под root стартует и так.
  - `--isolated` обязателен: профиль в памяти, иначе параллельные Cyrus-сессии дерутся за один user-data-dir.
  - **Артефакты:** снимки и логи консоли идут в `--output-dir` = `.playwright-mcp/` внутри воркгри (в `.gitignore`). ⚠️ **На скриншоты это не распространяется:** относительный `filename` сервер считает от КОРНЯ воркспейса (Cyrus передаёт его как MCP root), а не от `--output-dir` и не от рабочей папки процесса — менять `cwd` бесполезно, проверено. Правило: имя скриншота задавать как `.playwright-mcp/<имя>.png`, иначе картинка ложится в корень репо. Страховка на забывчивость — `/*.png|jpg|jpeg` в `.gitignore` (картинок в корне у нас нет, все в `public/`).
  - **SPA-грабли:** `browser_navigate` возвращается по `load`, а React ещё грузится → первый скриншот ловит спиннер. Перед snapshot/screenshot всегда `browser_wait_for`.
  - Как и остальные MCP, требует allow-list `mcp__playwright` в Cyrus `/settings/tools` (вкладка Linear) — иначе Cyrus откажется звать тулы.
  - **Доступ на dev = один файл сессии `/data/.cyrus-playwright-auth.json`** (на томе, вне репо), который обёртка отдаёт сервером через `--storage-state`. В нём лежат сразу две вещи: кука обхода Vercel и залогиненный тестовый пользователь. Благодаря ему агент открывает `https://dev.triplanio.com/trips` напрямую, без SSO и без экрана логина — проверено скриншотом 2026-08-01.
    - `dev.triplanio.com` закрыт **Vercel Deployment Protection** (302 на `vercel.com/sso-api` — это НЕ логин приложения). Ключ для автоматики — Protection Bypass for Automation: секрет проекта заведён в env Cyrus как `VERCEL_BYPASS_SECRET`, первый переход на `…/?x-vercel-protection-bypass=<secret>&x-vercel-set-bypass-cookie=true` отдаёт `307` и ставит куку. **Защиту с превью при этом НЕ снимаем** — она остаётся включённой, отзывается ротацией секрета.
    - Логин — мусорным аккаунтом dev-Supabase (`claude1@test.com`, без Pro и чужих данных). Так задумано: у 0.0.78 механизма «введи пароль не показывая модели» НЕТ (`--secrets` затирает секреты только в ОТВЕТАХ тулов; в схемах `browser_type`/`browser_fill_form` поля `secret` нет), поэтому аккаунт обязан быть одноразовым. Селекторы формы: `#l-email`, `#l-pw`, сабмит по Enter; **сначала закрыть баннер cookie** («Necessary only»), иначе он перекрывает форму.
    - **Протухание решено автоматически.** Файл истекает вместе с refresh-токеном Supabase, поэтому обёртка сама пересоздаёт его через `scripts/agent/playwright-auth.mjs`, если файла нет или он старше недели. Креды берутся ТОЛЬКО из окружения Cyrus (Railway): `PW_TEST_EMAIL`, `PW_TEST_PASSWORD`, `VERCEL_BYPASS_SECRET`. Нет переменных → сервер просто стартует без сессии (видны лендинг и публичные страницы), не падает.
    - ⚠️ **Пароль в `memory/` не кладём** — эта папка в гите, и правило «no secrets» в блоке Memory в `CLAUDE.md` про это же. Хранение пароля не помогло бы протуханию: перелогин всё равно нужен, а env-переменная делает его автоматическим, тогда как записанный в память пароль требует ручного захода.
    - Грабля резолва: скрипту нужен `playwright-core` **той же версии, что и браузер**, а в репо такой зависимости нет. Берём из дерева, которое `npx` разворачивает под сам MCP: `npx -y -p @playwright/mcp@<ver> sh -c 'NODE_PATH=$(echo "$PATH" | cut -d: -f1 | sed "s#/\.bin$##") node …'` — `npx -p` кладёт `.bin` пакета первым в `PATH`, но `NODE_PATH` НЕ ставит, поэтому его выводим из `PATH`. Ставить `playwright-core` в `package.json` не нужно и вредно: разъедется с билдом браузера.
- **Прочие MCP в сессии:** `cyrus-docs` (дока Cyrus — поиск/чтение), `cyrus-tools` (служебные: self-report фейлов, агент-сессии Linear).

Память агента грузится так: корневой `CLAUDE.md` авто-инлайнит `@memory/MEMORY.md` (индекс) в каждую сессию → этот файл агент открывает по указателю из индекса. Подробнее о механизме — блок «Memory» в `CLAUDE.md`.
