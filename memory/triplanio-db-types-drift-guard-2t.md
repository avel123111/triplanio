# Triplanio: типы схемы БД в репо и гард 2t на дрейф (TRIP-383)

Ф0.5 эпика **TRIP-374** («единая дверь в данные»). Продуктового кода не тронуто ни
строки; **ни одна edge-функция на типы не переписана** — это по мере касания
(рост диффа лишает шаг откатываемости).

## Что появилось

| Файл | Роль |
| -- | -- |
| `supabase/functions/_shared/database.types.ts` | генерируемый артефакт схемы: 41 таблица + 6 вью = **47 `Row`**, **0 нативных enum** |
| `scripts/ci/check-db-types.mjs` | **судья**: закоммиченные типы vs типы из `supabase/migrations/**` |
| `scripts/ci/check-db-types.test.mjs` | 16 тестов, без Docker и сети |
| `.github/workflows/checks.yml` → джоба `db-types` | **производитель**: Docker + Supabase CLI |

Артефакт лежит там, откуда его импортит шов Ф1 (`_shared/mutate.ts`) — то есть в
**edge**. Фронту он сейчас не нужен; понадобится — решается при касании.
**Руками файл не правится**: он обязан быть воспроизводимым выводом
`supabase gen types typescript`, иначе гард ловит собственную правку как дрейф.

Нативных enum в схеме **ноль** — статусы держатся на 76 `CHECK`. Следствие для
шва Ф1: `status` приезжает в типах как `string`, и сужение до литералов —
работа руками, а не подарок генератора.

## ★★ Ограничение способа проверки — главное, что надо знать

Генерация типов **читает живую базу**. В CI живой базы нет, и звать оттуда
настоящую dev **нельзя**: миграция из PR к моменту прогона ещё не задеплоена
(деплой идёт ПОСЛЕ мерджа), поэтому сверка «типы из PR ↔ живая dev» была бы
**красной на каждом ПРАВИЛЬНОМ ходе**. Гард, красный на правильном ходе,
выключают — это отдельно записанный закон репо ([[triplanio-ci-guard-is-code]]).

Поэтому 2t поднимает **свой** postgres, накатывает на него `supabase/migrations/**`
и сверяет **МИГРАЦИИ ↔ ТИПЫ**:

* **ЛОВИТ**: «миграция поменяла схему, а типы не перегенерили».
* **НЕ ЛОВИТ**: правку схемы **мимо миграции** (дашборд, ручной SQL). Она уводит
  живую БД от репо, и типы останутся верными ОТНОСИТЕЛЬНО РЕПО, будучи неверными
  относительно базы. Этот класс закрывает не 2t, а инвариант авто-деплоя
  «репо == dev == prod» ([[triplanio-cicd-github-actions]], [[triplanio-migration-naming-drift]])
  и живой ассерт ярусов ([[triplanio-security-tiers-architecture]]).

Отвергнутая альтернатива — эвристика «файл миграции тронут → требуй правку
типов». Она **не проверяет соответствие**: миграция сплошь и рядом схему не
меняет (`REVOKE`, `CREATE POLICY`, правка тела функции) — гард краснел бы на них
и молчал бы на переименовании колонки внутри уже тронутого файла.

## Замер dev ↔ prod ПЕРЕД генерацией (обязательный стоп-гейт)

Если проекты разошлись, типы молча зафиксируют один из них. Замер 2026-08-09:
схемы **идентичны** — 41 таблица / 6 вью / 472 колонки / 104 функции / 0 enum,
**одинаковые md5** сигнатур колонок и функций, обе базы PostgreSQL 17.6, журналы
миграций по **96 записей** с максимумом `20260805210500` = ровно 96 файлов в
`supabase/migrations/` (незадеплоенных миграций нет).

★ **Сверка сделана С ДАТЧИКОМ**: тем же запросом снят `count(city_visits)` —
**534** против **226**. Без него «одинаковые хэши» одинаково хорошо объяснялись
бы тем, что инструмент оба раза сходил в ОДНУ базу. Это тот же приём, что
«датчик слепоты» у пробы tsc в [[triplanio-ts-check-ratchet-2s]]: сверка,
которая не доказала, что видит две стороны, ничего не доказала вообще.

## ★ Разделение «произвести» и «судить» — то, что даёт гарду тест

Docker поднимает **джоба**; `check-db-types.mjs` только **судит два текста**.
Поэтому его тест кормится фикстурами и не требует ни Docker, ни сети — а иначе
гард со спин-апом базы остался бы единственным в репо без теста.

Джоба живёт **отдельно от `guards`** по той же причине, что 2o/2p/2q: у `guards`
намеренно нет ни `npm ci`, ни Docker. Работает **только на PR в `dev`** — дрейф
входит в кодовую базу правкой, а правка входит через PR; гонять спин-ап базы ещё
и на каждом push в dev/main значило бы удлинять цепочку деплоя (`checks.yml` —
её гейт) ради вопроса, на который уже ответили на PR.

**CLI пинован той же версией, что в `supabase-deploy.yml` (2.108.0).** Две версии
генератора в одном репо = расхождение вывода, которое читается как дрейф схемы.

## ★★ Датчик слепоты: пустая база даёт ВАЛИДНЫЙ файл

Если база не поднялась или миграции не накатились, генератор печатает исправный
TypeScript с `Tables: { [_ in never]: never }`. Отсюда два провала сразу:
сверка **двух** пустых зелена ПО ПОСТРОЕНИЮ, а сверка пустого с настоящим красна
по **неверной причине** («типы устарели» вместо «база не поднялась»). Поэтому обе
стороны сначала проверяются на признак жизни, и его отсутствие = код **2 «не смог
измерить»**, а не 1 и тем более не 0: «нечего проверять» и «проверено, чисто» не
должны печатать одинаковый вердикт.

## ★★ Исключений НЕТ вовсе — и это результат замера, а не аскезы

Первая редакция генерировала артефакт **облачным** генератором (Management API), а
сверяла с выводом **локального** CLI — и заводила исключение под
`__InternalSupabase.PostgrestVersion` («версия рантайма, а не схемы»).
Первый же прогон в CI показал, что рассуждение было **правдоподобным и неверным**:

* схема сошлась **ПОБАЙТОВО** — 2649 строк, 47 таблиц/вью с обеих сторон;
* разошёлся ровно блок `__InternalSupabase`, которого локальный CLI **не эмитит
  вообще** (не «другое значение версии», а отсутствие ключа).

Причина была не в версии рантайма, а в **двух разных генераторах**. Лечение —
не исключение, а **один генератор на обе стороны**: артефакт коммитится тем же
`supabase gen types typescript` пинованной версии, которым его проверяет джоба.
Сверка стала побайтовой, а у гарда не осталось ни одного обхода — как у 2q/2s.

**Цена названа:** в артефакте нет `__InternalSupabase.PostgrestVersion`, поэтому
`createClient<Database>` возьмёт своё умолчание про версию PostgREST. Понадобится
шву Ф1 — блок появится от смены версии CLI (той же, что в `supabase-deploy.yml`),
а не от правки файла руками.

★ **Побочный результат того же прогона, ценный сам по себе:** реплей
`supabase/migrations/**` на чистый postgres даёт РОВНО ту схему, что стоит на
живой dev. То есть схлопнутый baseline (TRIP-68, [[triplanio-migration-naming-drift]])
**воспроизводим**, а не «работает, пока не трогаем» — это первая машинная
проверка этого свойства с момента реконсиляции.

★ **Урок общего вида:** «исключение, которое кажется про природу данных, бывает
про инструмент». Прежде чем заводить обход — проверить, не собраны ли стороны
разными производителями.

## ★★ Дефект, который нашёл собственный тест, а не чтение кода

Датчик жизни считал таблицы по **СЫРОМУ** тексту (`/^\s*Row: \{$/gm`), и таблицы
выпадали из наблюдения **ЦЕЛИКОМ** у файла с **хвостовыми пробелами**
(`Row: {   ` — якорь `$` уже не сходится): гард печатал «не смог измерить» на
здоровой генерации. Ровно тот класс, что «предикат, чувствительный к ФОРМЕ
ЗАПИСИ, — дыра по построению» (TRIP-388). Лечение: считать по **нормализованному**
тексту. Урок для будущих гардов: нормализация обязана идти РАНЬШЕ любого
предиката, а не только перед финальным сравнением.

⚠️ **Первая редакция этой записи (и комментария в гарде) называла причиной CRLF —
и это НЕВЕРНО, поймано прогоном на проходе `code-simplifier`.** У JS-регулярки в
многострочном режиме `$` сходится и перед `\r`, поэтому `Row: {\r\n` предикат на
СЫРОМ тексте считает верно: прогон с восстановленной «первой редакцией» на чисто
CRLF-фикстуре печатает `сгенерировано 1 таблиц/вью` и выходит 0. Красным тот же
прогон делает фикстура с хвостовыми пробелами. Правило отсюда общее и уже
записано в [[triplanio-ci-guard-is-code]]: **правдоподобное объяснение красноты —
не замер**; причина отказа называется тем же прогоном, что и сам отказ, иначе в
память уезжает урок про механизм, которого нет.

## Мутации: чем доказано, а не сколько их

Финальный прогон судящей половины — **11 мутаций, 11 красных**, каждая с
проверкой, что она **применилась** (`md5` до/после):

| Что ломал | Красных из 17 |
| -- | -- |
| сверять СЫРОЙ текст вместо нормализованного | 2 |
| снять датчик жизни целиком | 4 |
| снять клаузу «есть корень схемы» | 1 |
| не нормализовать CRLF | 1 |
| не срезать хвостовые пробелы | 1 |
| regex таблиц без флага `m` | 9 |
| `die()` выходит 1 вместо 2 | 8 |
| дрейф выходит 0 вместо 1 | 6 |
| снять `try/catch` у чтения стороны | 1 |
| снять раннюю проверку «не передан путь» | 1 |
| не печатать расхождения в дифф | 2 |

★ **Две мутации в промежуточном прогоне выходили ЗЕЛЁНЫМИ** — нашёл
`code-simplifier`, и обе про один узор: *проверка стоит на случае,
отфильтрованном РАНЬШЕ неё*. Датчик жизни — И-условие из двух клауз, а
фикстура-мусор (`Error: connection refused`) отсекалась ПЕРВОЙ (ноль таблиц),
так что вторая («есть корень схемы») не была запинена ничем; у пустого пути обе
ветки дают 2, а тест смотрел только код выхода. Лечение — фикстура «таблицы
есть, корня схемы нет» и ассерт на СВОЁ сообщение.

★ Он же нашёл единственную ветку, где **коды 1 и 2 разъезжались**:
`existsSync` говорит «да» и про каталог, `readFileSync` бросает `EISDIR`,
непойманное исключение уводит node на **1 = «дрейф»**, хотя не измерено ничего.
Лечение — `try/catch` → `die()`.

⚠️ **Правило отката мутации: КОПИЯ ФАЙЛА, а не `git checkout --`.** Грабля уже
записана в [[triplanio-ci-guard-is-code]], и я влетел в неё ВТОРОЙ раз: откат
восстановил гард из устаревшего индекса и стёр разом правки
`code-simplifier` и свою починку кодов выхода, а параллельно `perl -0pi` в
цикле мутаций **утроил файл** (452 строки, три `import` подряд). Знать грабли
мало — восстановление должно не зависеть от индекса.

⚠️ Ещё две мутации **не применились с первого раза** (`sed`/`perl` не нашли
якорь) и печатали «тесты зелёные» — то есть «ничего не проверено» в одном ряду
с пойманными. Отсюда: **сначала `md5` до/после, потом счёт красных**.

Производящая половина проверена **отдельным draft-PR**: фиктивная миграция,
добавляющая колонку, без регенерации типов. Демонстрация не смешана с рабочим
PR намеренно — мёрдж фиктивной миграции накатил бы её на живую dev.
