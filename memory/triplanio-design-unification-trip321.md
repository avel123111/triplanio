# Triplanio: почему стилей тысячи — 261 пространство имён вместо дизайн-системы (TRIP-321)

Диагноз, ради которого стоило открывать TRIP-321. Слой над
[[triplanio-typography-canons]] и [[triplanio-surface-canons]]: те задачи сводят
ЗНАЧЕНИЯ, а корень — в том, что сводить нечего, потому что нет компонентов.

## Счёт (замерен 2026-08-01)

| | |
| -- | -- |
| Объявлений в CSS | 2 213 |
| Инлайновых объявлений в JSX | 2 412 |
| **Итого стилевых объявлений** | **≈ 4 600** |
| Уникальных CSS-классов | 1 334 |
| **Разных префиксов классов** | **261** |
| Всего JSX-элементов | 5 246 |
| Из них сырых `<div>`/`<span>` | 2 685 (51%) |
| Из них компонентов `src/design/` | **301 (5.7%)** |
| Инлайн-стилей `style={{…}}` | 776 |

Приложение на 30-40 примитивах держит 300-500 объявлений. У нас в десять раз
больше, и множитель — не количество экранов, а **261 пространство имён**.

## Где сидит множитель

Кластеризация всех 1729 CSS-правил по НАБОРУ свойств: **37 «форм» объявлены
заново в 4+ разных префиксах**, и это 525 правил из 1729.

| Правил | Префиксов | Что это на самом деле |
| -- | -- | -- |
| 61 | 36 | `display:flex + align-items + gap` → **Row** |
| 48 | 32 | `+ flex-direction` → **Stack** |
| 45 | 29 | `+ color` → Row с приглушённым текстом |
| 31 | 25 | `width+height+border-radius+background+color` → плитка-иконка |
| 22 | 19 | `display:grid + gap + grid-template-columns` → **Grid** |
| 22 | 17 | плитка + `border` → кнопка-иконка |
| 22 | 13 | `width+height+border-radius` → квадрат/аватар |
| 18 | 17 | `svg { width+height+color }` → размер иконки |
| 15+13 | 27 | точка/свотч |

Те же формы сидят и в инлайнах: `display` 237 · `gap` 143 · `alignItems` 92 ·
`flexDirection` 55 = ~530 объявлений, которые дословно есть Row и Stack.

**Примерно десять примитивов поглощают ~340 CSS-правил и ~530 инлайнов.**

Живая иллюстрация — один объект «квадратная плитка-иконка 22-34px» объявлен как
`.ai-blk-ic`, `.ai-file .di`, `.ai-file-x`, `.ev-dlg-close`, `.hv-plat__ic`,
`.hv-cancel__ic`, `.tv-carrier__av`, `.pt-cstop__hotel .ic`, `.pt-mapcap__pill`.

`src/design/index.jsx` экспортирует 16 компонентов, и **все они про содержимое**
(Btn, Card, Badge, Field, Dialog, Avatar). Примитивов РАСКЛАДКИ нет ни одного —
поэтому `display:flex` пишется руками 237 раз.

## Откуда это взялось: два механических порта, а не «накопилось»

**1. Макет → JSX «один в один».** Каждый экран рисовался ОТДЕЛЬНЫМ HTML-файлом
(`LUMO DESIGN SYSTEM.html`, `TRIPS_STATS_REDESIGN_LUMO_V3`,
`TRIP_SCREENS_NOHEADER_LAYOUT`, `FORK_PANEL_HOTELS_LUMO`, `OVERVIEW_REDESIGN_LUMO`,
`TRIPLANIO_ACCOUNT_LUMO` и др.), и в каждом автор брал себе префикс, чтобы классы
не столкнулись: `pt-`, `ai-`, `hv-`, `tv-`, `te-`, `ts-`, `bgt-`, `dl-`, `eed-`,
`s22-`, `fork-`, `tl3-`, `ncal-`, `vp-`, `cbar-`… Перенос «пиксель в пиксель»
импортировал вместе с макетом его ПРИВАТНОЕ пространство имён. В HTML-макете нет
компонентов — там дивы со стилями, поэтому импортировалась вёрстка вместо
архитектуры. Улика: `ManualPlanner.jsx` имел **145 инлайн-стилей в первом же
коммите** — файл таким РОДИЛСЯ, они не накапливались.

**2. Tailwind + shadcn → свой CSS «пиксель в пиксель» (TRIP-53).** Прямая цитата
из шапки `EventEditDialog.css`: «1:1 visual port … so the result is
pixel-identical». Каждый утилити-класс заморожен в литерал: `w-3.5`→14px,
`p-2.5`→10px, `rounded-sm`→`calc(var(--radius) - 8px)`. Из удалённого
`tailwind.config.js` приехало ровно то, на что потом жаловались:
- `boxShadow: {soft, card, pop}` → те самые «три параллельных шкалы теней»
  (Lumo завёл свои `--sh-1/2/3` и старые НЕ удалил);
- `borderRadius: {lg/md/sm}` от `--radius` + произвольные `rounded-[Npx]` →
  зоопарк радиусов. Никто не выбирал 23 радиуса, их выбрал Tailwind;
- shadcn-конвенция `--primary: 211 72% 46%` (голая HSL-тройка, обязана
  оборачиваться в `hsl()`) → при уходе с Tailwind часть мест осталась с голым
  `var(--primary)`, значение невалидно, браузер молча выбрасывал объявление, и
  **35 мест не красились в фирменный синий**. Это артефакт миграции, а не
  небрежность.

Оба порта были разумны в моменте (нулевой риск сломать вид). Цена — весь чужой
произвол въехал в код навсегда, и задачи «унификации» (TRIP-53, 165, 189, 321)
месяцами разгребают последствия ПО ОДНОЙ ОСИ за раз.

## Что с этим делать (план, согласован 2026-08-01)

1. **Перекрыть источник.** Макет — картинка, а не исходник. Новый экран не
   заводит свой префикс; новый префикс — только с явного одобрения Pavel. Без
   этого шага любая чистка натечёт обратно.
2. **Дописать примитивы РАСКЛАДКИ** в `src/design/`: `Row`, `Stack`, `Grid`,
   `IconTile`, `IconButton`, `Dot`/`Swatch`, `Icon`. Они не изобретают вид, а
   фиксируют существующий → визуально ноль изменений. Требует апрува по правилу #6.
3. **Схлопывать по ОДНОМУ ЭКРАНУ = один PR**, от тяжёлых: `ncal` 156 классов ·
   `bgt` 153 · `acct` 139 · `pt` 137 · `chat` 129 · `dl` 122 · `te`+`ts` 157.
   Приёмка — скриншоты до/после (Playwright, [[triplanio-agent-connectors]]).
   Честно: это недели, не часы.
4. **Мерить пространства имён, а не значения:** префиксов 261 → ~30, классов
   1334 → ~400, объявлений 4600 → ~800, доля дизайн-системы 5.7% → 40%+.

## Грабли

**Массовый прогон по значениям ломает живое.** Ф3b свела 111 литеральных радиусов
на шкалу — и на элементе 17px ступень 11px дала идеальный круг: `.checkbox input`
уехал в прод РАДИОКНОПКОЙ (экран входа + фильтр Viator). Браузер зажимает радиус
до половины стороны, причём зажимается НОВОЕ значение. Кандидаты на вырождение:
свотчи, квадратики легенды, логотипы партнёров (у них ещё `object-fit:cover` →
круглый кроп), точки-индикаторы, чекбоксы. Проверять надо по ПРАВИЛУ целиком:
`width/height` и `border-radius` сплошь и рядом на разных строках.

**Гард против такого прогона строить НЕ надо — надо не делать прогонов.** Забор
на радиусы был написан и снят в том же PR: его храповик ключевался на ТЕКСТЕ
СЕЛЕКТОРА, а при схлопывании экранов селекторы переименовываются пачками, то есть
инструмент блокировал бы ровно ту работу, ради которой строился. Общее правило:
прежде чем строить забор, спросить, не мы ли сами копаем яму, от которой он
защищает.

**Ложное срабатывание опаснее пропуска.** Детектор вырождения читал `min-width:0`
(стандартная флекс-идиома) как «сторона = 0»: гард, который валит CI на обычном
приёме вёрстки, не чинят, а глушат целиком.

**Свой одноразовый скрипт анализа — такой же подозреваемый, как чужой.** Обзор дал
«21 сырой радиус, 8 в приложении»; настоящих было 2 — скрипт заглатывал соседние
свойства JSX-объекта через запятую (`borderRadius: 4, fontWeight: 700` читался как
радиус 700). Цифру из грепа нельзя докладывать фактом, пока она не воспроизведена
вторым способом. Зеркало
[[feedback-dead-i18n-key-sweep-must-scan-backend]] — свой прогон тоже.

**Скан по литералам врёт в обе стороны.** Из 1572 классов «неиспользуемых» 73, но
41 собирается шаблоном `` `btn--${variant}` `` и живой; реально удаляемых было 7.
Обратно: имя иконки приходит ИЗ ДАННЫХ (`budget_categories.icon`), проверять надо
`src/` + `supabase/functions/` + `supabase/migrations/` + саму БД.

**`design-token-exempt` обязан стоять НА строке объявления** — гард читает
построчно, маркер в комментарии НАД строкой не работает.

**Гард считается работающим, только если назван шагом в `checks.yml`.**
`check:design` существовал с TRIP-53, звался BLOCKING в CLAUDE.md и памяти — и не
запускался на PR ни разу. «Зелёный локально» не доказывает ничего.

## Что при этом реально починено (PR #634)

Настоящие баги, которые видел пользователь: голый `var(--primary)` (35 мест не
красились + скрытые: белый текст на светлом в выбранной строке, невидимое
активное состояние кнопки карты, отсутствующее фокус-кольцо); тёмная тема
требовала два механизма и применялась наполовину (теперь ОДИН слой в `app.css`,
класс `.dark` выпилен, тема только через `data-theme`); круглый чекбокс; белый
`#fff` поверх `--brand` в тёмной теме (2.2:1 → `--primary-fg`). Остров `.auth`
(`login.css`) пинит свою светлую палитру, поэтому обязан пинить и семью
`--primary-*`, иначе при смене системной темы на экране входа `--brand` остаётся
светлым, а `--primary-fg` проваливается в тёмный.
