Копирование трипа.

- Edge `copyTrip` (POST {tripId}): доступ к исходному трипу = `isCallerParticipant` (иначе 403); копия принадлежит вызывающему (created_by), `is_pro_trip:false`. Копируются города/отели/активности/переезды/trip_services. Участники НЕ копируются (и не нужны: `is_trip_participant` покрывает владельца через `created_by`, как и у `create_trip` — строки-владельца в `trip_members` не заводит ни один из путей).
- **Лимит НЕ считается в самой функции** — его добивает BEFORE INSERT триггер `trips_enforce_limit` (`enforce_trip_limit`, фри = 1 активный собственный трип), единый источник для ВСЕХ путей создания. Вставка нового трипа идёт первой, поэтому over-limit фри-юзер отлетает ДО копирования детей; `TRIP_LIMIT_REACHED` (P0001) маппится в чистый 403. Не выдумывать вторую проверку Pro внутри функции: канон статуса — `subscription_status === 'pro'` + непросроченный `subscription_end_date` (как `isProActive`/`getUserPlan`), и он уже зашит в `is_user_pro`.
- **Название копии локализовано** по `users.language` вызывающего (он же владелец копии), фолбэк на en: `Копия: X` / `Copy of X` / `Copia de X`. Префикс ЛЮБОГО языка сначала срезается регуляркой, собранной из той же карты префиксов, поэтому копия копии не растёт. Обрезка под `trips_title_len` (300) идёт по КОДОВЫМ ТОЧКАМ (`[...s].slice()`), а не `.slice()`: `char_length()` в Postgres считает кодовые точки, срез по UTF-16 разрубил бы суррогатную пару и отдал бы Postgres битый UTF-8.
- **Частичная копия невозможна:** каждое чтение источника и каждая вставка детей проверяет `error` и падает громко, а недоделанная копия сносится компенсирующим DELETE (все дочерние таблицы `ON DELETE CASCADE` на `trips.id`; Telegram-интеграций и Storage-документов у секундной копии не бывает, поэтому голого DELETE хватает, teardown из `deleteTrip` не нужен). Сбой самого отката вклеивается в переброшенное сообщение вместе с id осиротевшего трипа — иначе он был бы невидим в Sentry. Раньше вставки детей молча глотали `error` и юзер получал `ok:true` + навигацию в трип без части броней.
- Триггеры на вставке детей копию НЕ ломают: `trg_notify_booking_added` никого не спамит (`x.uid <> actor_id`, а участник у свежей копии только автор), `trg_seed_budget_on_trip`/`trips_create_group_chat` штатно засеивают копию.
- **Pro НЕ наследуется**: из копируемого `details.addons` вырезаются Pro-only аддоны (`budget`, `chat`, `telegram_assistant`); фри-аддоны (`calendar_view`, `hotels_selection`) сохраняются. Список синхронен с `src/lib/tripAddons.js` PRO_ONLY_ADDONS — менять в обоих местах.
- **Документы/обложка-ФОТО НЕ копируются (TRIP-15 Этап B, решение Pavel 2026-06-24, задеплоено prod v24 + dev v26):** копия рождается без единого следа документов. В `copyTrip`: `trips.cover_image_url → null`; `hotel_stays`/`activities`/`transfers.documents → []` (стрипается из спреда + явный `documents: []`); `trip_services.details` клонируется без ключа `documents` (остальные ключи — provider/booking — сохраняются); `trip_documents` не копируется (как и раньше). Файлы Storage оригинала не трогаются → новые копии файлов с оригиналом НЕ делят (закрыт прежний footgun общих файлов). Документы = Storage-бэкнутые сущности, физического дублирования файлов нет. PR #115.
- **Градиент обложки НАСЛЕДУЕТСЯ (TRIP-107, PR #174):** в отличие от фото (Storage-документ, не копируется), `cover_gradient` — это просто id из нашего набора 16 (`src/lib/trip-gradients.js`), поэтому `copyTrip` теперь ставит `cover_gradient = sourceTrip.cover_gradient || 'gradient_1'`. Раньше не переносил → копия с NULL → UI рисовал legacy-процедурный градиент (баг). Инвариант по всему приложению: `cover_gradient` всегда непустой (DB `DEFAULT 'gradient_1'` + backfill NULL + coalesce в `ManualPlanner`/`SettingsLens` save), фото рендерится поверх. Единый рендер-хелпер `coverGradientCss()` (без процедурных/hsl/`var(--primary)` фоллбэков — те выпилены из `Trips.jsx`/`ManualPlanner`/`VisitPanel` вместе с мёртвыми `strHue`/`coverHue`/`accentHue`).
- UI: **единственная** точка входа — карточка «Копия путешествия» (`settings.copy_trip_*`) в `SettingsLens`, стоит ВНЕ read-only fieldset, поэтому доступна каждому участнику, включая viewer (копия своя, оригинал не трогает). Пункта «Дублировать» в `MoreMenuDialog` больше НЕТ. На успех — тост `trip.copy_done` + nav на `/trip/:newId`; на ошибку — реальное сообщение сервера, уже распарсенное `invokeFn` (повторно читать `error.context` НЕЛЬЗЯ, Response читается один раз).
- **Порядок: клик → confirm → гейт лимита → копирование.** И confirm (`confirm.copy_trip.title`, кнопка = существующий `common.copy`, вариант `default`, не destructive), и гейт лимита (`TripLimitDialog`) живут в ШВЕ `startCopy` в `CreateTripProvider`, а НЕ на экране с кнопкой — вторая точка входа унаследует их по построению, а не форкнет поведение одного элемента ([[feedback-unify-behavior-across-identical-elements]]). Confirm взят обычный resolve-true/false, НЕ async-режим `onConfirm`: между подтверждением и копированием стоит лимит-гейт, и спиннер на кнопке диалога висел бы над не той работой. In-flight фидбэк — блок-оверлей `trip.copying`. `ConfirmProvider` в `App.jsx` смонтирован ВЫШЕ `CreateTripProvider`, поэтому `useConfirm()` там доступен.
- Тех-долг (не баг, замерено при аудите): `city_visits` вставляются в цикле по одной (нужен маппинг старый id → новый), а `trg_recompute_on_transfer_ins_del` — FOR EACH ROW, то есть полный `recompute_trip` на каждый вставленный переезд. Итог корректный (последний пересчёт видит всё), но работа кратная числу городов/переездов.
