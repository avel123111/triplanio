★РЕШЕНИЕ 2026-06-07 (Pavel): карта не должна ре-рендериться при каждом открытии экрана. Делаем ОДИН `mapboxgl.Map` на всю апу/сессию, который «телепортируется» (DOM appendChild) между экранами. Охват = ВСЯ апа, включая create-флоу (выбран максимальный вариант, не trip-scoped).

Почему так: инстанс карты живёт пока жив React-компонент (`new Map` в useEffect([]) → `map.remove()` при unmount). Раньше overview пересоздавал карту при каждом заходе, а map lens висел скрытым (display:none latch) → бывало 2+ живых WebGL-контекста + капали Map Loads. Подробности раскладки экранов см. рассуждения; три отдельных инстанса были: overview→RouteMapCard→MapView, map lens→ScreenMap→MapView, planner→FlowMap (другой компонент).

Границы (важно, Pavel спрашивал): singleton убирает ТОЛЬКО лишние пересоздания внутри одной живой страницы. Не переживает: перезагрузку/новый день/другое устройство/другого юзера — это всегда новый Map Load (живую карту закешировать нельзя, кешируются только тайлы). Смена трипа в рамках сессии — НЕ пересоздаёт (провайдер над роутером). Кросс-сессионную/кросс-юзерскую стоимость на витринных экранах (Overview) решает не singleton, а статичная картинка (Static Images API, кешируется CDN) — отдельный рычаг, ещё не делали.

АРХИТЕКТУРА: `src/lib/map/MapProvider.jsx` (новый) — context над роутером в `App.jsx` (внутри ConfirmProvider, оборачивает Router+Toaster, покрывает и PublicTrip). Лениво создаёт 1 карту в off-screen holder-div, `acquire(slot,scheme)` = appendChild контейнера в слот + resize(rAF), `release(slot)` = парк обратно в holder (с guard «не красть, если новый владелец уже взял»). `useSharedMap()` hook. ИНВАРИАНТ: одновременно смонтирован только ОДИН MapView (иначе дерутся за единственный элемент).

ФАЗА 1 СДЕЛАНА (2026-06-07, dev, build+check:design зелёные, браузер-верификация на Pavel):
- MapView.jsx: init-эффект `new Map/remove` → `acquire/release`; при unmount чистит свои маркеры + слои mv-dashed/mv-solid (инстанс живёт дальше); `ready` сидится из isStyleLoaded (нет флеша спиннера при возврате). Вся draw/focus/projection/theme логика без изменений.
- TripView.jsx: выпилен latch `mapEverShown` + display:none-обёртка; map lens теперь `{shownLens==='map' && <ScreenMap/>}` (условный монтаж — иначе overview+map оба acquire конфликтуют).
- App.jsx: смонтирован `<MapProvider>`.
- Потребители RouteMapCard/ScreenMap/TripStructureEdit/PublicTrip не меняли (тот же API MapView).

ФАЗА 2 СДЕЛАНА (2026-06-07; ★с TRIP-520 09.2026 FlowMap УДАЛЁН — визард рисует общий `MapView`, см. «ОДНА ОБОЛОЧКА» ниже): FlowMap.jsx переведён на общий инстанс (acquire/release), как MapView. Чистит свои слои flow-dashed/flow-solid + маркеры при unmount; ready/readyRef из isStyleLoaded; на переиспользованном инстансе явно применяет scheme+projection (его theme/proj-эффекты не зависят от ready). FlowMap остаётся ОТДЕЛЬНЫМ компонентом (своя draw-логика по данным home/cities/returnCity/transport), но делит ОДИН инстанс с MapView — компоненты не сливали, слили инстанс. ManualPlanner (manual+AI, /new-trip и /plan-trip-ai) рендерит один FlowMap на роут; переход create→/trip/:id сохраняет карту (провайдер над роутером). Конфликта за единственный элемент нет: planner-роуты и trip-роуты не пересекаются.
ФАЗА 3 СДЕЛАНА (2026-06-07, dev, build+lint+check:design+тесты 32/32 зелёные, браузер на Pavel): вынес общий `src/lib/map/routeLines.js` → `drawRouteLines(map, legs, {dashedId,solidId,dashedColor,solidColor,...})` — единое правило линий (no kind→dashed, flight→geodesic arc, road→straight+OSRM-апгрейд, else→solid) + отмена pending OSRM. MapView и FlowMap теперь только строят свои legs ({from,to,kind}) и зовут хелпер (mv-* ROUTE_COLOR op.4; flow-* MISSING/accent op.5). МАРКЕРЫ НЕ сливал намеренно — разные (нумерация+группировка+клик vs SVG-метки home/return), объединение дало бы ветвление, не ясность. Дублей линий/OSRM больше нет.

ФИКС ФОКУСА (2026-06-07, dev): после singleton фит ломался при переходе между экранами (map→overview слишком близко, overview→map камера высоко). Причина: acquire делал resize() только в rAF, а draw/fit-эффект потребителя отрабатывал раньше в том же flush — fitBounds считал зум по размерам ХОЛСТА ПРЕДЫДУЩЕГО экрана. Фикс: синхронный map.resize() в acquire ДО фита (rAF оставлен подстраховкой). MapProvider.jsx.

ИТОГ: цель «рендерить карту один раз» достигнута полностью (Фазы 1–2); Фаза 3 — дедуп без смены поведения. Осталось вне этой инициативы: статика на витринах (Overview как кешируемая картинка) для кросс-сессионной/кросс-юзерской стоимости — отдельный рычаг, НЕ начат. Notion-док по карте ещё не обновлён.

★ШОВ ЛЕНИВЫХ ЧАНКОВ (TRIP-520, 09.2026): синглтон переживает смену маршрута только если оба экрана меняются ОДНИМ коммитом React. С TRIP-445 экраны едут отдельными чанками под `Suspense fallback={<AppLoading />}`, а `<AppLoading>` держит ЗАСТАВКУ ЗАПУСКА — поэтому первый вход в чанк за сессию (успех визарда → `/trip/:id`) без транзишна размонтировал визард, показывал заставку и лишь потом монтировал трип: человек видит «перезагрузку страницы», карта паркуется в holder и переезжает через пустой кадр. Фикс системный, своего кода перехода ноль: `<BrowserRouter future={{ v7_startTransition: true }}>` — React держит старый экран, пока новый не готов (замер на стенде: `SSSSSSSTTT` с флагом против `FFFFFFFTTT` без), плюс прогрев чанка `import('@/pages/TripView')` в момент сохранения рядом с прогревом запросов — к нажатию «Открыть» ждать нечего. Экран успеха при этом рисуется ВНУТРИ оболочки визарда (карта + панель/шит + прогресс), а не ранним `return` со своей шапкой: успех — финал флоу, не отдельная страница; терминальность держит `savedOk` в памяти визарда (браузерный «назад» меняет `?step=`, рисуется по-прежнему успех). Проверка без логина: Vite-стенд в scratchpad с подменой дверей `@/lib/AuthContext`/`@/lib/invokeFn` через alias, заглушки `VITE_SUPABASE_*` в окружении (клиент создаётся на уровне модуля), Chromium `/opt/pw-browsers/chromium` с `executablePath`.

★КАРТА ПРИНАДЛЕЖИТ СЕКЦИИ, А ПАНЕЛЬ — ДАННЫМ (TRIP-520, 09.2026). Синглтон переживает смену экрана, но не переживает смену ВЛАДЕЛЬЦА СЛОТА: у секции «Маршрут» было две оболочки — `EditSkeleton` в `TripView` с пустым слотом (`map={null}`) и `MapShell` внутри `EditLens`, — и они сменяли друг друга по состоянию загрузки; на «создал трип → открыть трип» карта парковалась в holder на время запросов (~0.5–1 с при клике до прихода прогрева) — «карта исчезает и появляется через секунду». Правило: секция монтирует ОДНУ оболочку с живым `MapView` сразу, скелетон занимает только панель (`EditLens` при `draft === null`, флаг `loading`; города для карты — `buildDraft(shell, [], lang).nodes` из shell, редактор ждёт content); `TripView` секцию `route` не гейтит по загрузке, только по ошибке. Второй шов того же перехода — ВОЗДУХ КАДРА: визард кадрировал с 48/32–40, `MapView` — с литералом 60, цели камеры не совпадали и `calmFit` ехал всегда (минимум 420 мс). Закон один — `fitAir(phone)` в `lib/map/insets.js`, режим раскладки отдаёт вызыватель (`useIsPhone`/`PHONE_MAX_W`); правка видима на всех читателях `MapView` (редактор, обзор, публичный трип, демо), апрув Pavel. Разница осталась одна: полоса пилюли визарда меряется из DOM, у трипа её нет. Проверка без токена: слот `.mapshell__map` обязан существовать в КАЖДОМ кадре перехода (стенд: `kkkkkEEEE` — скелетон панели со слотом, затем редактор; ни одного кадра без слота).

★ОДНА ОБОЛОЧКА НА ВИЗАРД И ТРИП (TRIP-520, 09.2026, финал). Плавным переход «создан → маршрут» стал только тогда, когда перестало быть ЧТО монтировать заново: `TripShell` — элемент раскладки роутера (layout route в `AuthenticatedShell`, lazy) на три адреса `/new-trip`, `/plan-trip-ai`, `/trip/:tripId`; ключ внешней `ErrorBoundary` внутри зоны один (`trip-zone`), свою границу по адресу оболочка держит сама вокруг `<Outlet/>`. Экран под ней НИЧЕГО общего не рисует, а публикует (`src/components/trips/TripShellContext.jsx`): факты шапки/рейла `useShellFacts({mode, tripId, addons, section, step, isPro, proResolved, title, meta, loading, backTitle}, cbs)` — в `useLayoutEffect` (оболочка перерисовывается ДО кадра; уборка публикует «пусто», уходящий и приходящий экран сводятся в один коммит), колбэки — ссылкой на каждый рендер; поверхность карты `useShellSurface(config, mapProps)` — конфиг `MapShell` состоянием оболочки, пропы `MapView` — ОТДЕЛЬНЫМ стором (`useSyncExternalStore`), подписан только хост карты, чтобы ховер по ряду не перерисовывал рейл; содержимое — `ShellSlot name=…` ПОРТАЛОМ в узлы, которые держат `TripShell` (`content` = ящик у `.trip-content`, `shell` = оверлеи, `main` читается) и `MapShell` (`panelHead/panelBody/panelFoot/panelOverlay/status/mapOverlay`, узлы отдаются хосту через `onSlot(name, el)`; `PeekSheet` отдаёт свой скроллер через `onBodyRef`). `MapView` один на оба экрана внутри `MapShell` (`SurfaceHost`), `FlowMap` распущен в него: пустой маршрут = стартовый глобус (`globeStart`, подпись — размер окна, `markFramed`, чтобы первый город ПРИЕЗЖАЛ), обложка холста до `framed` (спиннер только пока грузится стиль), пилюля «N городов · M ночей» — слот `status`, который `MapShell` МЕРЯЕТ и отдаёт кадру закрытым снизу (`mapShellInsets.statusPx`). ★РЕЙЛ — СЛОЙ, И В ВИЗАРДЕ ЕГО НЕТ (решение Pavel): логотип, выход и меню принадлежат рейлу; в визарде он убран за левую кромку (`--rail-inset: 0px` на `.trip-shell`, `visibility: hidden`), шапка визарда во всю ширину со своей круглой «назад» (тот же `onBack`, что на телефоне), панель у края холста, камера с отступом 620. На переходе в трип оболочка ставит `--rail-inset: 70px` (число из `cssPx('var(--rail-w)')`, оно же уходит `MapShell` пропом `insetLeft`) — и одним темпом поверхности едут ЧЕТЫРЕ вещи: рейл выезжает (`transform` по `--rail-inset`), шапка отодвигает отступ (`padding-left` у `.app-header--trip`, транзишн — у правила оболочки `.trip-body > .app-header`, иначе его перебивает специфичность), панель и тумблер шелла карты уезжают правее (`left`, `--mapshell-inset-left` ставит сам `MapShell` из пропа), камера доводит 620 → 690 (`useMapInsets`). Заголовок трипа проступает (`fadeIn` по `data-entering`, который оболочка ставит сама по смене режима `create → trip`; `location.state.from` больше нет). Кнопка «назад» шапки уходит в момент флипа (рейл накрывает её место за темп выезда). `MapShell` МЕРЯЕТ только ШИРИНУ панели (ResizeObserver), положение берёт числом: во время транзишна `left` замер с DOM врал бы, а RO смены позиции не видит. Шапка — во всю ширину сетки (`grid-column: 1 / -1`), рейл над ней (`z-index: 2`). Ловушка стенда: swiftshader даёт ~4 fps, CSS-транзишны стартуют с первого отрисованного кадра, а `easeTo` — с вызова, поэтому в журнале они выглядят рассинхронно; в живом браузере оба стартуют из одного коммита. Не повторять: (1) «рейл стоит в визарде пустым, въезжают пункты» — снимает движение вместо того, чтобы его сделать; (2) второй логотип на время выезда или логотип как элемент оболочки с режимным фоном — костыли. `bleed`/`flush` выводятся из объявленной поверхности (`data-surface`), поля `bleed` в реестре секций больше нет. ТЕЛЕФОН: шапки в визарде нет (Pavel 2026-08-18), поэтому секция с картой лежит и ПОД шапкой (`grid-row: 1 / -1` на ≤640), шапка над контентом (`z-index`), в визарде уезжает `translateY(-100%)` и въезжает на переходе; закрытую ею полосу оболочка отдаёт числом `insetTop` → `MapShell` ставит камере (`topPx`: сдвиг холста = половина РАЗНИЦЫ шита и шапки, кадр симметричен) и CSS (`--mapshell-inset-top`, читает `.map-ctl`). Узлы визарда едут в `MapView` как visits (kind/координаты/id; `sortVisits` стабилен без дат), ховер/выбор — по id узла (спец-ключей `'home'/'finish'` нет). Замер стенда: десктоп 1440 — холст 1440→1440, pad 690→690, центр неподвижен, только штатный зум 7.19→7.26 (ушла полоса пилюли); телефон 390×844 — холст 390×844→390×844, шапка −60→0 за темп поверхности, сдвиг 287→257, камера стоит. Ловушки: `useLayoutEffect`-публикация обязана быть ДО ранних `return` экрана (экран лимита визарда публикует факты без поверхности); callback-ref'ы слотов обязаны быть стабильными (новая функция на рендер = снятие/постановка узла = петля ре-рендеров); `useShellSurface` без конфига ничего не снимает (встроенный `EditLens` в ящике календаря иначе снёс бы чужую поверхность).
