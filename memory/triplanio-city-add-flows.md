## Главный факт: словарь видов ОДИН, а вводится тремя способами

Планировщик уже собирает на сохранении (`ManualPlanner.jsx` ≈1150–1166) ровно тот
же словарь `kind`, что и редактор маршрута:

| вид | откуда берётся в планировщике |
|---|---|
| `start` | отдельное поле `home` — **шаг 1** «Откуда» |
| `transit` | строка списка, `nights > 0` — **шаг 2** |
| `waypoint` | строка списка, `nights === 0` — **шаг 2, степпером** |
| `end` | узел `finishCity` — **шаг 3** «Возврат» |

То есть «научить планировщик принимать start/end» НЕ НУЖНО — он их принимает.
Одно понятие «вид точки» размазано по трём шагам и трём способам ввода. Это и
есть причина, почему флоу читается как нелогичный.

## Четыре входа для города на двух экранах

1. **Планировщик, строка списка** (`CityRow` variant planner): «Добавить город» →
   в конец падает ПУСТАЯ строка-поле → тап по полю → шторка → выбор СТЕЙДЖИТСЯ →
   тап ✓ → коммит. **3 тапа вокруг самого выбора**, последний переспрашивает то,
   что уже выбрано.
2. **Планировщик, якорь старта на шаге 2** (`create/anchors.jsx`, `CityAnchorRow`):
   свой мини-флоу «нажал → появился инпут → выбрал».
3. **Планировщик, шаг 1** (`StepHome`): `CityPicker` прямо в форме.
4. **Редактор маршрута** (`EditLens.CityAdder`): «Добавить точку» → шит-композер →
   тап по полю → ВТОРАЯ шторка поверх первой → выбор → вернулись в композер →
   тип → «Добавить». **4 тапа и две вложенные поверхности.**

## Три дефекта, общие для обоих экранов

* **Контейнер приезжает раньше содержимого.** Тап «добавить город» ведёт не к
  поиску города, а к пустой коробке, где надо нажать ещё раз.
* **Подтверждается уже принятое решение.** Тап по городу в списке результатов и
  ЕСТЬ выбор. Причина подтверждения в коде названа честно («случайный тап по
  результату больше не коммитит город»), но ответ на случайный тап — отмена
  ПОСЛЕ, а не подтверждение ДО: строка уже на экране.
* **Шаг типа почти всегда no-op.** `transit`↔`waypoint` уже переключаются
  степпером ночей на строке (`EditLens.jsx` ≈715–735, `isPlannerWaypoint`), а
  `start`/`end` — роли по одной на трип, выключенные, если заняты.

Отдельная дыра: **в планировщике город нельзя изменить** — в коде так и написано:
«change a city by deleting + re-adding».

## Запрос Pavel (последний) и план

Хочет: в планировщике такая же шторка, как в редакторе — выбор города + выбор
`start/waypoint/transit/finish` + подтверждение ВНУТРИ шторки; одна
УНИФИЦИРОВАННАЯ шторка на два экрана вместо двух разных.

**Ф1 — унификация без нового зоопарка (небольшая правка).** `CityAdder` из
`EditLens` переезжает в общий модуль (он уже самодостаточен: `onAdd(city, kind)`,
`hasStart`, `hasEnd`) и работает на обоих экранах. В планировщике принимает
`transit`/`waypoint`; `start`/`end` ВЫКЛЮЧЕНЫ существующим `disabledFor`, потому
что их задают шаги 1 и 3. Из `CityRow` уходят `editing`/`staged`/кнопка ✓.
Даёт: одна шторка на два экрана · минус вложенная поверхность · минус
подтверждение-в-строке · минус четвёртый вход (`CityAnchorRow`).

**Ф2 — только после ответов Pavel.** Включение `start`/`end` в шторке. Без него
получится ТРИ способа задать старт вместо двух.

## Открытые вопросы (нужен ответ Pavel, без него Ф2 делать нельзя)

1. **Убрать подтверждение?** Случайный тап по результату будет сразу добавлять
   город; страховка — видимая строка, которую можно удалить/перевыбрать.
2. **Что с шагами 1 и 3**, если старт и финиш можно задать в шторке: остаются
   (дубль), схлопываются, или мастер становится трёхшаговым?
3. **`StepReturn` — не выбор города.** Там три режима, и «останусь» узла НЕ
   СОЗДАЁТ: он помечает последний город `kind:'end'`. В шторке «город + его вид»
   такого режима нет и быть не может — он про отсутствие переезда, а не про
   город. Значит шаг 3 либо остаётся ради него одного, либо «останусь» переезжает.

## Грабли, заложенные в задачу

* `waypoint` в планировщике выражен НОЧАМИ (`nights === 0`), а не полем. Выбор
  «пересадка» в шторке и степпер в строке станут двумя источниками одного факта —
  свести одним предикатом сразу, иначе разъедутся молча (класс TRIP-277).
* `start` в планировщике — НЕ элемент списка. Выбор «старт» должен не добавить
  строку, а перезаписать поле шага 1 (в редакторе на этом месте `arr.unshift`).
* НЕ ПРОВЕРЕНО: ляжет ли десктопный инлайн-вариант `CityAdder` в раскладку шага 2
  планировщика (там свой список строк), и переживут ли классы `te-add*` переезд
  без новых имён (гард 2m).
