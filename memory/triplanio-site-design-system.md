TRIP-446 Ф1 фундамент сайтовой дизайн-системы — общего CSS для маркетинга/публичных/юридических страниц вне логина. Эпик «неавторизованная зона» = TRIP-445 (handoff в Linear-документе, §3/§13); родственная работа — [[triplanio-public-trip-redesign]].

**Где живёт.** `public/site.css` (переименован из `landing.css`). Обслуживает восемь маршрутов: лендинг (`LandingPage.jsx`), публичный шаринг (`PublicTrip.jsx`), `/terms`, `/privacy`. Файл НЕ бандлится — грузится рантаймом `<link>`-инъекцией на React-роутах и статическим `<link>` на юр-страницах.

**Токены на `html.site`, а НЕ на голом `:root`.** Класс `site` вешает `useSiteCss()` (`SiteChrome.jsx`) на `document.documentElement` при монтировании и снимает на unmount — один механизм включает/выключает сайтовые токены. Почему класс, а не `:root`:
- Голый `:root` из бандлящегося файла — это прод-инцидент [[triplanio-login-css-token-leak]] в полный рост: действовал бы на всех маршрутах постоянно. `html.site` не может утечь по построению — нет класса, нет токенов.
- Тёмная тема не под ударом: `app.css` объявляет тёмное в `:root[data-theme="dark"]` (специфичность 0,2,0), `html.site` — 0,1,1; более специфичный выигрывает независимо от порядка. Алиасы `--X: var(--Y)` во `html.site` вычисляются НА элементе — см. [[triplanio-css-alias-frozen-at-root]].
- **Проверено в браузере (не рассуждением):** `body { color: var(--ink); background: var(--white) }` наследует токены с `<html class="site">` → рендер байт-в-байт как со старым `:root`. Без класса `--ink` не определён (текст чёрный на прозрачном) — ровно поэтому статические `/terms` и `/privacy` несут `class="site"` прямо в разметке (React на них не исполняется, `useSiteCss` не срабатывает).

**Примитивы (общие, без префикса):** `btn`, `btn--primary`, `btn--white`, `btn--ghost`, `btn--lg`, `header`, `footer`, `container`, `eyebrow`. BEM с ДВОЙНЫМ дефисом (`btn--primary`, не `btn-primary`). Уникальное для страницы — свой namespace: `auth-`, `join-`, `doc-`, `pt-`, `dt-`. `.site` — хост токенов, не семья (аналог `:root`). `cflag` в сайтовую ДС не тащить — это примитив приложения ([[triplanio-country-flag-primitive]], живёт в `app.css`).

**Правило «старый CSS умирает вместе со страницей».** `src/pages/login.css`, `src/pages/PublicTrip.css`, константа `STYLES` в `JoinTrip.jsx` остаются на месте до Ф6: там страницы переписываются с нуля, старый файл удаляется, новые правила пишутся сразу в `site.css` тем же PR. Перенос сейчас — работа на выброс, и он недоказуемо «ни пикселя» (другая позиция в каскаде: бандл vs рантайм-инъекция).

**Гарды, видящие файл:**
- **2ac `check-site-prefixes.mjs`** (`npm run check:site-prefixes`, TRIP-446) — ратчет namespace'ов ТОЛЬКО для `public/site.css` по образцу 2m: префикс класса, которого нет нигде в базовой версии файла, роняет PR; escape `/* prefix-exempt: <prefix> — причина + апрув */`. Ловушки: (1) БАЗА резолвит файл по имени — `public/site.css`, иначе `public/landing.css` (карта переименования, чтобы бутстрап-PR не покраснел на пустой базе); (2) хост-класс `.site` исключён из счёта на ОБЕИХ сторонах — иначе стал бы «известным префиксом» и открыл бы `.site-*` молча. Гард 2m (`check-css-prefixes`) сайтовый файл НЕ видит — он сканирует только `src/`.
- **2k `check-design-tokens.mjs`** — типографику в `site.css` ЕНФОРСИТ, но файл в шести allow-листах (SCAN_EXTRA, COLOR, WEIGHT_LH, LAYERS, BREAKPOINT, SPACING), т.е. выведен из этих ярусов.
- **2n orphans / 2u css-comments** — сканируют `public/`, файл видят.
- 2p `check:semantics`, 2l inline-styles — НЕ видят (собирают только `src`).

Гард 2ac — код, у него есть тест `check-site-prefixes.test.mjs` (шаблон [[triplanio-ci-guard-is-code]]: временный git-репо, гард подпроцессом, был увиден КРАСНЫМ мутацией; отдельный кейс на бутстрап «на базе файл под старым именем»).

## TRIP-447 Ф2 — общая оболочка (SiteHeader/SiteFooter)

`SiteChrome.jsx` переведён на новый дизайн: ОДНА шапка и ОДИН подвал на всех восьми маршрутах, состав — пропсами, а не шестью похожими копиями. Потребители в том же PR: `LandingPage.jsx` (`src/pages/Landing/`) и `PublicTrip.jsx`.

1. **Контракт темы шапки.** `SiteHeader` с пропом `themed` читает `document.querySelectorAll('[data-hdr]')` на секциях страницы и вешает на `<header>` класс `on-<значение>`. Три и только три значения: `light` / `dark` / `accent` — у каждого свой ПОЛНЫЙ набор правил в `site.css` (7 / 7 / 9 правил; базовый `.header` структурный, ни одного emitted-класса без правил). Значение берётся из `sections[i].dataset.hdr` **без проверки**: опечатка в `data-hdr` даст класс `on-<опечатка>`, под который правил нет, и шапка молча останется без темы. Дефолт при `sections.length === 0` — `light` (безопасный).
2. **Пересчёт `recalc()` — три точки:** скролл (`passive`), монтирование (+ `requestAnimationFrame`), смена маршрута. Открытие страницы и переход между маршрутами скролла НЕ вызывают — без ручного пересчёта тёмная секция получит тёмный текст (ловушка handoff §11.14).
3. **`on-accent` — производитель есть (TRIP-460):** секция «Финальный CTA» лендинга несёт `data-hdr="accent"` (`.final.dark`, закатный градиент прототипа) — она и включает 9 правил `.on-accent`. Контраст шапки в этом состоянии доведён до AA: `.main-nav a` полный `#fff` (4.76:1, было `rgba(255,255,255,.82)`=3.77), `.header-cta` текст `#C9481F` (4.74:1, было `#E0592E`=3.72).
4. **Состав шапки — проп `variant`** (`SiteHeader`): `full` (меню + CTA + бургер) / `cta` (логотип + язык + CTA) / `minimal` (логотип + язык). Не булевы флаги (`showNav`/`showCta`/`showBurger` выводятся из `variant`). На мобиле `full` прячет CTA в drawer — так в прототипе (`@media (max-width:900px){ .header-cta{display:none} .burger{display:grid} }`). Тема (`themed`) — только лендинг; в демо и авторизации ноль вхождений `on-*`.
5. **Имена классов — прототипные, переносятся как есть (TRIP-460, отменяет прежнее решение Ф2).** Оболочка и страницы зоны несут ИМЕНА ПРОТОТИПА 1:1: `site-header`/`site-footer`/`wrap`/`main-nav`/`burger`/`lang`/`lang-btn`/`lang-menu`/`logo` и весь хвост секций лендинга. Прежняя редакция Ф2 велела переименовывать в репозиторные (`header`/`nav`/`langdd`/…) — это решение СНЯТО: замер показал, что имена прототипа с `app.css` не конфликтуют вообще (`.site-header`/`.wrap`/`.main-nav`/`.lang-btn`/`.burger` встречаются в `app.css` ноль раз), а именно переименование в «репозиторные» само создавало поверхность коллизий (`.nav`/`.footer`/`.eyebrow`/`.sheet`). Правило фазы Ф6: берём прототип, а не пересказываем; CSS и разметка едут дословно, сверху только React-обвязка + `t()` + носители аналитики. Namespace-семьи прототипа (≈124) приняты под ОДНИМ блоком `/* prefix-exempt: … */` в `public/site.css` — точка апрува видна в диффе (апрув Pavel 24.08.2026), гард 2ac проверяет `npm run check:site-prefixes`. Семь имён, реально конфликтующих с правилом-одиночкой `app.css` (`btn`/`btn-primary`/`btn-ghost`/`sheet`/`eyebrow`/`bud-total`/`cflag`), разрешены по таблице тикета: один объект → зона несёт только вариант (не переобъявляет базу `.btn`, гард 2ae `check-site-primitive-dup`); разные объекты → своё имя (`.brow` вместо `eyebrow`, `.sheet-pane` вместо `sheet`); у переключателя языка флага нет → правило `cflag` не нужно.
6. **Метка кампании.** Правая кнопка шапки гонится через `withVisitCampaign()` (иначе `gclid`/`utm` не переживут клик — `url_passthrough` gtag читает их из адреса), переход через роутер (`nav()`), не `<a href>` — полная перезагрузка убивает снимок `entrySearch`. Правило переходов и его гард — в разделе TRIP-456 ниже.
7. **Граница двух ДС** — гард `check-ds-boundary.mjs` + тест `check-ds-boundary.test.mjs` (тот же шаблон [[triplanio-ci-guard-is-code]], увиден КРАСНЫМ мутацией). ЗАПРЕЩЕНО в зоне: визуальные компоненты `@/design/*` (`Btn`/`Card`/`Badge`/`Field`/`Checkbox`/`Avatar`/`EmptyState`…) и `src/design/app.css`, включая side-effect-импорт без `from` (`import '@/design/app.css'`). РАЗРЕШЕНО явным списком: `@/design/icons`, `MapView` (один инстанс Mapbox на сессию), `ConsentBanner` (рендерится над роутером), всё из `src/lib/**`. Расширение списка — с апрувом Pavel. **В CI гард включается только в Ф9** — до переписывания страниц (Ф6) он КРАСНЫЙ по построению (публичка ещё тянет `Avatar`), поэтому вне глоба `npm test`.

## TRIP-456 Ф2а — аналитика и атрибуция под гардом

Слой атрибуции самый хрупкий в эпике: все способы его сломать НЕВИДИМЫ (приложение выглядит и работает одинаково, разница — только в Network или на аудите через месяцы). Полный контекст — handoff §9. На `main` и `dev` слой побайтово одинаков.

**Снимок адреса `entrySearch`** (`src/lib/analyticsEnv.js`) — `window.location.search`, взятый ОДИН раз при загрузке модуля и живущий в памяти документа. Из него `campaign.js` достаёт метки кампании (`gclid`/`utm_*` → `camp_*`). Полная перезагрузка документа обнуляет память модуля → снимок и метка теряются. Поэтому взятие на верхнем уровне модуля (а не в функции) — намеренно: внутри функции снимок захватил бы адрес ПОСЛЕ первой клиентской навигации.

**Два инварианта держит гард 2j (`check-analytics-seam.mjs`), а не проза** (правила D и E, добавлены поверх A/B/C; тест `check-analytics-seam.test.mjs` увиден КРАСНЫМ мутацией):
- **D.** Единственный в репо `supabase.auth.signUp` несёт `signup_attribution: getSignupMarks() || undefined` (`Login.jsx`). Это ЕДИНСТВЕННЫЙ носитель меток через границу «письмо подтверждения → другое устройство» (ссылку часто открывают на телефоне, где снимка визита нет). Читается в `AuthContext.jsx`, кормит колонки `users.signup_utm_*`. Больше ОДНОГО `signUp` быть не должно — второй = второе место рождения аккаунта, две разные истории атрибуции (падает отдельным сообщением). Ноль `signUp` = пустая комната, а не «чисто» ([[triplanio-ci-guard-is-code]]).
- **E.** Каждый `signInWithOAuth` / `signInWithIdToken` предваряется `rememberAttributionForRedirect()` в ТОЙ ЖЕ функции (проверка через глубину скобок: между ними глубина не падает ниже уровня функции). Три входа сегодня: Google redirect, Google One Tap (вызов в `try`), Apple. Четвёртый провайдер без этой строки молча теряет атрибуцию. `signInWithPassword` НЕ покрыт намеренно (документ не покидает; жёсткая навигация после него — уже при наличии сессии, терять нечего).

**Правило переходов + гард 2ad (`check-site-nav.mjs`).** Внутренние переходы между маршрутами приложения — через роутер (`<Link>` / `nav()`), не `<a href>`: полная перезагрузка убивает `entrySearch`. Гард флагит СТРОКОВЫЙ литерал `href="/внутренний-путь"` в сайтовой зоне (`SITE_ZONE` = `src/components/site`, `src/pages/Landing`, `src/pages/PublicTrip.jsx`; в Ф6 список растёт с логином/join/юр-страницами). Тест увиден КРАСНЫМ мутацией. **Что гард НЕ запрещает** (перечислено в его шапке, чтобы правильный код не «чинили»):
- внешние ссылки (`https://`, `mailto:`, `tel:`);
- якоря (`#features`) — документ не перезагружается;
- ДИНАМИЧЕСКИЙ `href={…}` — `href={SITE}` в `PublicTrip.jsx` (`SITE = withVisitCampaign(origin+'/')`) = намеренная полная перезагрузка, метка едет В АДРЕСЕ; любое выражение `href={…}` вне счёта (читаются только литералы);
- `link.href = '/site.css'` (присваивание DOM-свойства в `useSiteCss`) — исключено `(?<!\.)` в предикате.
- жёсткую `window.location.href` ПОСЛЕ установки/сброса сессии (`handleLogin`, One Tap, `finishToLogin`) — намеренно; блок-запрет `window.location.href` покраснел бы на правильном коде, поэтому не делается.

**★ Ловушка:** сегодня в зоне ровно ДВА законных внутренних `<a href>` — `SiteChrome.jsx` → `/privacy` и `/terms`. Они статические HTML (rewrite в `vercel.json`), React-роута нет, `<Link>` дал бы 404. Идиом обхода — как `prefix-exempt` в 2ac: маркер в комментарии рядом, видимый в диффе: `{/* nav-exempt: /terms — статический HTML до Ф6 (vercel.json rewrite), <Link> дал бы 404 */}`. В Ф6 страницы становятся маршрутами, маркеры снимаются (пункт в [[triplanio-public-trip-redesign]]/TRIP-451), гард начинает их сторожить.

**`withVisitCampaign()` — четыре места на сегодня:** `SiteChrome.jsx:131` (`ctaTarget` шапки), `LandingPage.jsx:88` и `:565` (hero + финальный CTA), `PublicTrip.jsx:34` (константа `SITE`). Метка едет в АДРЕСЕ, поэтому переход этими ссылками = намеренная полная перезагрузка (снимок восстанавливается из URL на новой странице).

**PostHog грузится ДО согласия** (вариант B, [[triplanio-cookie-consent]]/TRIP-407): режим `persistence:'memory'`, события идут, на устройство не пишется ничего; согласие апгрейдит ТОТ ЖЕ клиент до `localStorage`. Формулировка «ноль байт до согласия» НЕВЕРНА — не тащить её в новые тексты (в т.ч. Privacy).

**Прочие приёмники/точки атрибуции** (чеклист «не потерять» при переносе страниц — постранично в TRIP-451): `user_signed_up` + `conversion('registration')` в `AuthContext.jsx`; `landing_viewed`/`login_opened` из реестра `screenOpenEvent` в `App.jsx` (новые маршруты вписывать туда); `@vercel/analytics` в `App.jsx` (третий приёмник); `postLoginRedirect` (пишет `JoinTrip`, читает `Login`).
