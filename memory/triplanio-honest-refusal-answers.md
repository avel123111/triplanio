# Triplanio: два врущих ответа — отказ приезжает статусом (TRIP-378)

Ф0.2 эпика «единая дверь» (TRIP-374; handoff — Linear-документ на эпике:
https://linear.app/triplanio/document/handoff-epik-edinaya-dver-v-dannye-trip-374-8720de36a6ec).
Живые дефекты, к архитектуре эпика отношения не имеющие. Тронуты РОВНО две
edge-функции и их вызыватели.

## Что было врущим → что стало

| Место | Было | Стало |
| -- | -- | -- |
| `deleteTrip` | `if (tripErr \|\| !trip) → 404` | настоящее отсутствие → **404 NOT_FOUND**; сбой запроса → rethrow → **500 INTERNAL** |
| `updateTripSettings` нет прав | `200 { ok:false, code:'FORBIDDEN' }` | **403 FORBIDDEN** |
| `updateTripSettings` нужен Pro | `200 { ok:false, code:'PRO_REQUIRED' }` | **402 PRO_REQUIRED** (+ `x-sentry-skip`, см. ниже) |
| `updateTripSettings` lookup | ошибка ОТБРАСЫВАЛАСЬ, падало в «Trip not found» | та же развилка, что в `deleteTrip` |

`.single()` отдаёт «ноль строк» ОШИБКОЙ, поэтому `tripErr || !trip` — не
небрежность, а естественная форма записи: она сама сливает «нет строки» и
«запрос не удался». Развод — на общей таксономии `isNotFound`
(`_shared/classifyDbError.ts`), тем же предикатом, что у `tripAccess`, чтобы две
двери не разъехались. Сбой не рендерится руками, а **пробрасывается**:
`withHandler` сам отдаст `{ error, code:'INTERNAL' }` 500 и положит в Sentry
НАСТОЯЩУЮ ошибку Postgrest (code/details/hint) вместо синтетического «ответил 500».
Цена вранья была не косметическая: **404 не ретраится**, владелец на свой же трип
видел тупик, а Sentry записывал 404 про наш сбой.

Коды НЕ переименованы намеренно: на них ветвится клиент, и переименование рвёт
группировку Sentry (запрет §0(F) хендоффа).

## ★★ Смена статуса меняет ещё и МОНИТОРИНГ, а не только клиента

`withHandler` репортит в Sentry **каждый** ответ `status >= 400` (кроме 401).
Пока отказ был 200, Sentry о нём не знал ВООБЩЕ — значит честный статус заводит
события там, где их не было. Для `PRO_REQUIRED` это ровно монетизационная
дорожка (не-Pro жмёт Pro-тумблер → клиент открывает апселл), то есть событие на
КАЖДЫЙ показ предложения. Поэтому 402 помечен `x-sentry-skip: '1'` — тем же
приёмом и по той же причине, что `createStripeCheckout` метит `TRIP_ALREADY_PRO`.
`FORBIDDEN` НЕ помечен намеренно: «залогинен, но нельзя» значит, что интерфейс
предложил действие тому, кому оно недоступно, — `_shared/http.ts` прямо называет
403 отчётным.

**Правило общего вида:** переводя отказ с 200 на честный 4xx, спроси не только
«что теперь увидит клиент», но и «сколько событий это заведёт в Sentry» —
нормальный бизнес-«нет» обязан нести `x-sentry-skip`, иначе честность ответа
покупается зашумлённым мониторингом.

## ★ Следствие для клиента: не белый экран, а ТИХИЙ промах

В ТЗ главным риском названо «`invokeFn` БРОСАЕТ на не-2xx → белый экран».
**Замером это не подтвердилось:** `functions-js` ловит и делает
`return { data:null, error }` (`FunctionsClient.js`, ветка `catch`), `invokeFn`
тоже возвращает. Бросков нет, белый экран невозможен.

Настоящий риск — тише и потому хуже: у не-2xx **`data` пуст**, поэтому ветка
`data?.code === 'PRO_REQUIRED'` перестаёт совпадать МОЛЧА. Ничего не падает,
просто вместо Pro-апселла показывается общий тост «не сохранилось» — деньги
теряются без единой ошибки где-либо. Код читается от `invokeFn` (он снял тело
ОДИН раз — `Response` читается единожды), и Pro-ветка — единственная, зависящая
от кода.

Тексты — одна точка `refusalToast` в `SettingsLens`: обёртка (`save_error` /
`save_error2`) + клауза по коду. Инвариант: **серверный текст пользователю не
показывается НИКОГДА**, незнакомый код → «попробуй ещё раз». Это не педантизм:
на 500 `withHandler` кладёт в тело `(e as Error).message`, то есть текст ошибки
БД, а прежний вызыватель удаления печатал в тост именно серверный `message`.
У удаления своя клауза: «нет прав менять настройки» про удаление врёт.

## Чем это удержано (у поведения нет скриншота и его не ловит ни один гард)

`src/lib/edgeError.test.js` — единственный машинный гейт класса: код переживает
не-2xx, `PRO_REQUIRED` остаётся отличим от `FORBIDDEN`, строка SDK
«Edge Function returned a non-2xx status code» не доходит до пользователя.
Проверен МУТАЦИЕЙ: снятие чтения `error.context` роняет 8 из 11.
⚠️ Мутация `perl` **не применилась с первого раза** (якорь не совпал) и печатала
зелёное = «ничего не проверено» — ловится только сверкой `md5` до/после.

## Грабли, стоившие времени

* **Гарды читают КОММИТ, а не рабочее дерево** (`git diff BASE_REF...HEAD`):
  до первого коммита 2l печатает «no source files touched — OK», а починка 2d в
  рабочем дереве не видна вообще. Прогонять после коммита/`--amend`.
* **2d читает НАПИСАНИЕ**: фикстура `'<html>gateway timeout</html>'` в тесте
  прочиталась как «hardcoded JSX text» (родня «комментарий, цитирующий проблемную
  форму»). Выход — `// i18n-ignore` на строке.
* `python3` в этом окружении **НЕТ** (в других записях памяти сказано обратное —
  проверять на месте); мутации гнать `node -e`.
* **Два числа про «сырые ответы» меряют РАЗНОЕ** и оба верны: **167** =
  однострочные `Response.json({ error })` (счёт §0(F) хендоффа), **193→188** =
  метрика M4 гарда 2r «ответ НЕ ПО КАНОНУ» (сверх тех 167 — двухаргументные,
  `ok:false`, `allow:false`, «только статус ≥400»). Очередное подтверждение
  «предикат раньше числа»; актуальное — `npm run check:door`.

## Границы

Остальные неканонические ответы НЕ тронуты — они уходят ОДНИМ codemod формы
(Р4 §0(F) отменил «по касанию»). `signupPrecheck`/`requestPasswordReset` держат
200 на отказ НАМЕРЕННО (анти-энумерация) и не трогаются никогда.

**Не закрыто и не выдаётся за закрытое:** сквозная ручная проверка трёх
состояний на живом стенде требует, чтобы функции были задеплоены, а деплой идёт
только мёрджем (правило 12) — то есть до мёрджа она физически недостижима.
До-мёрджевый гейт = тест + `check:door` + четыре яруса 2d (в т.ч. «ключи
резолвятся»). Ключи заведены в Tolgee (проект 2, en/ru/es) — сверено запросом.

**Отдельным следствием, вне этого тикета:** `withHandler` отдаёт КЛИЕНТУ
`(e as Error).message` в теле 500, то есть текст ошибки БД уезжает наружу у всех
44 функций. Клиент его не показывает, но в ответе он есть.
