# Triplanio: CI-гард — это код, и у него есть тест (гард 2l, TRIP-282)

★2026-08-02. В репо двенадцать гардов (2a-2l, `scripts/ci/*.mjs` +
`scripts/check-design-tokens.mjs`) и **ни одного теста ни на один из них**.
Гарды - единственный слой, который ловит то, что не ловят lint/typecheck/build,
и он же единственный слой без собственной проверки.

## Чем это кончилось

Первый вариант гарда 2l был храповиком поверх коммитимого файла
`scripts/ci/inline-style-baseline.json`. Через него уехали ЗЕЛЁНЫМИ три обхода:

- потолок поднимается правкой JSON руками (`count: 999` → `OK`);
- удаление baseline + `--write` заводит новый список с чем угодно внутри;
- новый файл вообще не проверялся по счётчику (`if (was && …)`), то есть
  ManualPlanner.jsx со 145 инлайнами - кейс, ради которого гард писался, -
  прошёл бы насквозь.

Корень один: **гард сверялся с артефактом, который сам же PR и правит.** У 2k в
шапке это записано одной строкой - «a count alone is bypassable» - и там же
реализовано лечение; прививка в репо была, её не применили.

## Как устроен 2l сейчас

Сравнение с БАЗОВОЙ веткой, коммитимого артефакта нет вообще:
`git diff --name-status --find-renames $BASE_REF...HEAD -- src/` даёт список
тронутых файлов, `git show $BASE_REF:<path>` - их прежнее содержимое. Правил
два: R1 счётчик инлайнов в тронутом файле не превышает базовый (у НОВОГО файла
база = 0), R2 нет новой группы из 3+ побайтово одинаковых (старые группы
grandfathered и могут только уменьшаться). Выход - построчный
`// inline-style-exempt: <причина>` для значений из данных (ширина в процентах,
цвет категории), как `i18n-ignore` у 2d и `ddl-guard` у 2b. Скан по
`.jsx/.tsx/.js`, комментарии гасятся.

Побочно исчезли: конфликты baseline при параллельных PR, мёртвые ключи,
красный CI на голом `git mv`, врущая сумма потолков.

## Что проверяет тест (`scripts/ci/check-inline-styles.test.mjs`)

Шаблон для остальных гардов: **поднять временный git-репо, запустить гард
подпроцессом, проверить код выхода** - то есть end-to-end, как в CI, а не
юнит-тест на внутреннюю функцию (все три обхода жили именно в I/O-обвязке, а не
в логике подсчёта).

Тест писался ПЕРВЫМ и падал на 9 случаях из 15. Он же поймал в переписанном
гарде ещё две дыры, которые я сам не увидел: запуск не из корня репо печатал
`0 changed file(s) — OK` на любом объёме грязи, и protocol-relative URL
(`src="//cdn…"`) читался как начало комментария и гасил стиль на той же строке.

★ Уроки, которые дороже конкретного гарда:
- «нечего проверять» и «проверено, чисто» не должны печатать одинаковый вердикт;
- ratchet без сверки с базой - это надпись, а не инвариант;
- у гарда обязан быть выход с ПРИЧИНОЙ рядом с кодом; 401-строчный baseline -
  это тот же allowlist, только без причин и без ревьюабельности.

## ★★ Escape обязан НАЗЫВАТЬ, что он гасит (TRIP-351, гард 2p)

Форма выхода у всех гардов репо одна: маркер в ДОБАВЛЕННЫХ строках диффа,
живёт один PR. Но у 2p он был написан как `if (exempt) process.exit(0)` -
**бланкетно**, то есть один маркер в PR гасил ВЕСЬ прогон. Цена замерена
прогоном, не рассуждением: маркер, поставленный на легитимный перенос правила,
пропустил в том же прогоне `.grow--fit padding: + 999px` - правку ОБЩЕГО класса,
которую видит каждый сидящий на нём элемент. Правило: маркер называет ключ
ЦЕЛИКОМ (`.checkbox {@media (max-width: 640px)} gap`), совпадать обязаны класс,
`@media`, состояние и свойство, остальные изменения продолжают блокировать.

★ Соблазн сократить маркер (опустить `@media`) - ревью Pavel развернуло его
одной фразой: **escape, который называет ключ НЕ ЦЕЛИКОМ, частично возвращает
дыру, ради которой недостающая часть в ключ и попала.** Media стоит в ключе 2p
потому, что мобильное правило ниже по файлу прячет правку десктопного (нашла
мутация, не чтение); маркер без media молча проезжал бы правку того же свойства
в мобильной ветке - на самом узком месте вёрстки. Форма: маркер без фигурных
скобок адресует базовый контекст и ТОЛЬКО его, мобильное называется отдельной
строкой; маркер = ровно то, что гард печатает слева от двоеточия. Так уже
устроены `floor-exempt: <метрика> +N`
(2o), `prefix-exempt: <префикс>` (2m) и построчные `inline-style-exempt` /
`i18n-ignore` - 2p был единственным исключением.

Соседний вывод оттуда же: **гард, красный на каждом ПРАВИЛЬНОМ ходе, будет
выключен** - и тогда он не поймает ничего. 2p не видит разметку и читает только
`.css`, поэтому переезд элемента на другой класс (канонический ход фаз 04-06,
~380 правил раскладки) был неотличим от сноса правила. Лечение - не ослабить
проверку, а дать ОБЪЯВИТЬ операцию: `visual-diff-move: <источник> -> <цель>`
сверяет, что ушедшие объявления есть на цели с теми же значениями; перенос со
сменой значения и маркер на несуществующую цель остаются красными. Границу такой
проверки надо называть вслух и не выдавать за большее: сверяются ОБЪЯВЛЕНИЯ, а
не то, что элемент действительно получил целевой класс.

## ★★ Число мутаций в отчёте - не доказательство (ревью Pavel, TRIP-351)

Отчёт «10 мутаций, каждая ловится» оказался на ТРИ пункта щедрее правды: строки
поиска в одноразовом мутационном скрипте устарели после смены формы предиката,
`replace` не находил ничего, и скрипт печатал такие мутации В ОДНОМ РЯДУ с
пойманными. Мутация, которая НЕ ЗАПУСКАЛАСЬ, - не «поймана» (тот же класс, что
«нечего проверять» ≠ «проверено, чисто», только про сам инструмент проверки).

Но починка скрипта закрывает половину, и вторая важнее: **скрипт мутаций лежит
вне репозитория и в PR не едет** - значит, он не переживает сессию, а строка
«N мутаций, все ловятся» ревьюеру непроверяема В ПРИНЦИПЕ. Отсюда правило:

- **отчитываться тем, ЧТО именно ломал и что при этом покраснело**, а не
  счётчиком (`снял сверку media → 3 красных`, `normMedia схлопнул любой запрос
  → 26 красных`);
- доказательство - мутация, которую делает РЕВЬЮЕР, и она делается на каждом
  гарде (на 2p Pavel сделал три своих: снятие сверки класса, снятие media,
  схлопывание `normMedia`);
- сам скрипт мутаций **не коммитить** - он станет очередным инструментом,
  требующим своего теста, а этой рекурсии в эпике уже хватит.

★ И снова: **зелёный тест ничего не значит, пока не увидел его красным.** У 2p
10 мутаций, каждая ловится своим тестом. Одну дыру - «класс не запинен в сверке
exempt» - нашла мутация в проходе `code-simplifier`, а не чтение кода: при 27
зелёных тестах маркер `.checkbox gap` тихо гасил бы `gap` у ЛЮБОГО класса,
потому что во всех фикстурах класс совпадал и предикат был невидим. Тот же класс
ошибки, что «163 токена двумя путями, один сломан» у 2o.

## ★★★ Ключ, названный не целиком, склеивает разные вещи в одну (TRIP-360)

Свойство ЛЮБОГО ключа в этих гардах, а не частный случай: за один день оно
всплыло трижды на одном и том же 2p.

1. **`@media`** не был частью ключа escape - маркер молча проезжал правку того
   же свойства в мобильной ветке, то есть в самом узком месте вёрстки (TRIP-351).
2. **Имя анимации**: шаг `from` сам по себе не единица. В репо 19 анимаций, и
   `from`/`to` повторяются в них по многу раз - ключ по одному шагу склеил бы
   `fadeIn` и `dockUp`, и ОДИН маркер гасил бы обе. Имя приходит из того же поля
   контекста, что и `@media` (это тоже родительский at-rule): `to {@keyframes
   dockUp} opacity`. Назвал Pavel до того, как замер это показал.
3. **Разделитель ключа**: `|` был безопасен, пока единицей был класс, и стал
   дырой, как только единицей стал произвольный селектор - `[lang|="en"]` и
   namespace `svg|a` легальны в CSS, ключ порезался бы по чужой границе. Отказ
   был бы в безопасную сторону (красный, не тишина), но объявить такое изменение
   автор не смог бы НИКАКИМ маркером. Лечится структурно (разделитель `NUL`,
   которого в CSS нет), а не строкой в шапке про то, чего гард не умеет. Нашёл
   `code-simplifier`, не чтение кода - второй раз подряд именно он.

## ★★ Слепая зона 2p: значения токенов и голые теги (TRIP-360)

Гард ключевался на КЛАССЕ, а у `:root` класса нет - правка альфы в семь раз
(`--brand-soft` `.14 → .99`) проезжала ЗЕЛЁНОЙ, и не ловил её при этом НИ ОДИН
гард репо: 2o сверяет СОСТАВ имён в `:root` и значения не читает, `check:design`
ищет сырые литералы (в `:root` литерал легален по построению), SPACING считает
только отступы. Причин две, обе структурные: правило без класса выпадало из
наблюдения, а у ПОТРЕБИТЕЛЕЙ токена сравнивается ТЕКСТ объявления -
`background: var(--brand-soft)` побайтово одинаков, что бы ни лежало в токене.

★ **Соблазн закрыть только токены (два адреса, +253 объявления) Pavel отверг:
закрыть узкое, оставив широкое.** Голый тег - это ОБЩЕЕ в чистом виде, `button
{}` и `h2 {}` бьют по всему приложению разом, шире любого токена; живой дефект
уже на руках и он именно там (`index.css:211-219` - второй полный канон
типографики на голых тегах, перебивающий `.t-*`), и без включения его снос
поехал бы вслепую ровно как тинт без токенов. Проверено: снос этого блока даёт
15 блокирующих строк, включая `h4 font-family: var(--font-display) →
var(--font-ui)` - ту самую подмену Golos на Exo. **Краснота на таком PR - ЦЕЛЬ,
а не издержка:** это намеренная правка общего, и маркер с причиной в диффе -
ровно та форма, в которой мы такое пропускаем (закон 6).

Устройство: единица наблюдения = `.класс` (с точкой) либо ЦЕЛЫЙ селектор, если
класса в нём нет; точка и разводит две ветки без отдельного флага. Оттуда же
следствие для маркера: **точка стала ОБЯЗАТЕЛЬНОЙ** - прежняя вольность
(`checkbox` = `.checkbox`) неоднозначна, раз `button` теперь законная единица, и
догадка за автора гасила бы не то. Правило одно и проверяемое глазом: **ключ
маркера = то, что гард НАПЕЧАТАЛ**. Островной словарь `login.css .auth` был под
наблюдением всегда (он класс) - запинен тестом, потому что единица переписана.
Границы названы вслух в шапке: `var()` по цепочке не резолвится (алиас
сравнится на своей строке), вычисленный цвет не считается, `@font-face` не rule
и `walkRules` его не видит. В отчёте два числа порознь (токены · прочее): ноль в
любой половине = ветка перестала мериться, суммарное число растворило бы пропажу.

★ Отчёт о мутациях в форме, которую требует раздел выше: 10 мутаций, все
ПРИМЕНИЛИСЬ (скрипт это проверяет отдельно) и все пойманы - вернуть
`if (!cls.length) continue` → 13 красных; выкинуть имя анимации из контекста →
2; снять нормализацию кавычек → 3; вернуть бесточечное имя как класс → 2; снять
из exempt сверку единицы → 3, media → 4, свойства → 2; схлопнуть бесклассовые
единицы в одну → 11; вернуть `|` разделителем → 1; ключевать целым текстом
селектора вместо класса → 2.

## ★★ Маркер тоже обязан называть ЦЕЛИКОМ - иначе он вынуждает ЛГАТЬ (TRIP-363)

Тот же закон, что про ключ, с другой стороны: у ключа он про склейку разного, у
МАРКЕРА - про ложь в диффе. 2p ключуется на КЛАССЕ, поэтому объявление
составного правила `.pro-up--inline .pu-body { flex: 1 }` приписывается ОБОИМ
классам, а источником `visual-diff-move` был ОДИН класс. Канонический ход фазы
05 (класс отдаёт раскладку, разметка уезжает на `.grow--fit`) закрывался
маркером только наполовину: `.pu-body` объявлен, `.pro-up--inline flex: − 1`
продолжает блокировать, и зелёным гард становился ТОЛЬКО от второго маркера
«`pro-up--inline` уехал на `grow--fit`» - **заведомо ложного утверждения ровно о
той разметке, которую маркер и удостоверяет.** Поводов солгать - 133 (составные
селекторы с раскладкой в `app.css`+`index.css`), то есть через два PR маркеры
перестали бы читаться как утверждения вообще. Это опаснее ложной красноты: гард
не выключают, а приучают писать в дифф неправду.

**Решение: источником может быть ЦЕЛЫЙ СЕЛЕКТОР** (`visual-diff-move:
.pro-up--inline .pu-body -> grow--fit`), одиночный класс работает как раньше.
Предикат единицы НЕ трогали - и это главный замер: единица «подлежащее»
(`.a .b` даёт раскладку `.b`) звучит честнее, но уносит из наблюдения **1926
ключей из 10844 и 64 класса целиком** (те, что живут в репо только предком), а у
`.a.b` подлежащего нет вовсе - оба класса на одном элементе (92 селектора).
Приписывание всем классам - огрубление в БЕЗОПАСНУЮ сторону, и менять его ради
красоты значило бы платить наблюдением.

★ **Скоуп по САМОМУ СЕЛЕКТОРУ, а не по набору его классов** - иначе маркер
`.wrap .pu -> grow--fit` погасил бы заодно снос НЕЗАВИСИМОГО `.pu { flex: 1 }`
со случайно совпавшим значением, то есть новую дыру того же класса, что и
лечится. Нашла её мутация (сверять набор классов вместо селектора), а не
рассуждение: она валит ровно один тест из 61. Для этого карта помнит
СЕЛЕКТОР-победитель, и он же **печатается справа от значения** (`.pro-up--inline
flex: − 1   (правило .pro-up--inline .pu-body)`): без источника в выводе автор
знает форму маркера, но не знает содержания - написать его не из чего. Слева от
двоеточия остаётся ровно ключ, потому что это форма `visual-diff-exempt`; сверка
идёт с уже напечатанным `unit+state`, иначе на `.btn:hover` подсказка была бы
дословным повтором ключа (нашёл `code-simplifier`, третий раз подряд именно он).

⚠️ Границы, названные вслух в шапке: скоуп точен настолько, насколько точен
каскад - карта помнит ОДНОГО победителя на ключ, поэтому независимое правило,
проигравшее каскад ТЕМ ЖЕ свойством, уедет под тем же маркером (воспроизведено);
требовать покрытия всех вкладчиков значило бы краснеть на правильном ходе.
**Открытый дефект, НЕ из этого захода:** `visual-diff-exempt` не умеет адресовать
бесклассовую единицу из нескольких лексем - в `h1 em color` шаблон берёт
единицей `h1`, а свойством `em`, печатает «под маркером изменений нет» и выходит
1, то есть такое изменение не объявляется НИЧЕМ. Живых таких единиц две (`h1 em`,
`h2 em`); чинится грамматикой `reExempt` (свойство = последняя лексема), но там
своя ловушка - опереться на «- причина» нельзя, разделитель пишут и дефисом.

★ Отчёт о мутациях: 8, все ПРИМЕНИЛИСЬ (скрипт проверяет отдельно) и все
пойманы - скоуп по набору классов → 1 красный; не печатать источник → 1;
печатать всегда → 1; вернуть узкий шаблон источника → 7; снять нормализацию
пробелов у комбинатора → 1; разрешить источником селектор без класса → 1; не
запоминать селектор-победитель → 5; подменить источник единицей → 5.

## TRIP-342: у маркера переноса дыра на стороне ЦЕЛИ (зеркало TRIP-363)

TRIP-363 чинил сторону ИСТОЧНИКА: маркер, названный не целиком, вынуждал лгать.
Фаза 05 упёрлась в ту же дыру с другого конца, и её надо знать до зон 2-6.

**1. Цель у `visual-diff-move` ровно одна, а раскладка уезжает на КОМПОЗИЦИЮ.**
Элемент отдаёт `display` примитиву `.row`, зазор - ступени `.row--g7`, перенос -
`.row--wrap`. Гард требует, чтобы ВСЕ ушедшие с источника объявления лежали на
НАЗВАННОЙ цели, поэтому второй маркер на ту же пару делает проверку СТРОЖЕ, а не
полнее: он начинает требовать `display` и от `.row--g7` тоже. Замерено прогоном -
44 несошедшихся переноса превратились в 91 после добавления вторых маркеров.

**2. Значения сверяются ТЕКСТОМ, `var()` не резолвится** (граница названа в шапке
2p). Поэтому честный перенос сырых `16px` на ступень `var(--sp-7)` - то есть ровно
то, ради чего шкала и заведена, - читается как «перенос СО СМЕНОЙ значения».

Следствие для 05: **каждое изменение объявлено `visual-diff-exempt` поимённо** (121
ключ в зоне 1, ноль бланкетных), а несверяемые `visual-diff-move` переведены в
прозу. Маркер, который гард считает ложным, - это ложь в диффе, то есть ровно то,
что TRIP-363 запрещал. Цена: ~120 строк исключений на зону, ~700 на эпик. Это НЕ
норма, а заявка на доработку 2p (резолвить `:root`-токены перед сравнением +
разрешить НАБОР целей), иначе к зоне 3 исключения станут шумом, в котором
настоящая правка не видна.

## TRIP-342: у `.row`/`.col` ДЕФОЛТНЫЙ зазор 10px - контейнер без зазора его получает

`.row{gap:var(--sp-5)}`. У флекса начальный `gap` = `normal` = 0. Значит перевод на
примитив контейнера, у которого зазора НЕ БЫЛО, молча раздвигает детей на 10px.
Таких правил 11 в зоне 1 и **78 по периметру** - им в приватном правиле явно
пишется `gap: 0`. Ни один гард этого не ловит: 2p видит `gap: + 0` как ДОБАВЛЕННОЕ
объявление и требует объявить его, но не подсказывает, что без него было бы
хуже. Проверяется рендером, как и половинчатая ступень.

★Половинчатая лестница выстрелила ВТОРОЙ раз, ровно как записано в `app.css`:
`.row--g1`, `.col--g2`, `.grid--g1` отдавали 10px вместо 2/4/2. Парность первых
двух возвращена, `.grid--g1` НАЗВАН оставшейся дырой в комментарии - чтобы
молчание перестало быть молчанием.

★Ещё раз про «зелёное ничего не значит, пока не видел красным»: сверка база-против-
HEAD по геометрии дала «совпало до пикселя», и это доказывало что-то только после
того, как мутация `.row--g7` 16px→15px была поймана (5 расхождений).

## TRIP-364 PR-A (PR #708): у маркера ДВЕ стороны, и обе называются целиком

Третья правка словаря 2p за сутки, теперь со стороны **ЦЕЛИ**. 351 научил
объявлять перенос, 363 - называть целиком ИСТОЧНИК, здесь - ЦЕЛЬ. Порок один и
тот же, вид разный: у ключа - склейка разного, у источника - вынужденная ложь, у
цели - **невыразимость**. Цель нельзя было назвать целиком в принципе:

1. раскладка уезжает не на класс, а на **композицию** (`.row` + `.row--g4`), а
   гард требовал ВСЕ ушедшие объявления на КАЖДОЙ названной цели - второй маркер
   делал проверку строже, а не полнее (44 несошедшихся → 91);
2. значения сверялись ТЕКСТОМ, поэтому перенос сырого `16px` на `var(--sp-7)` -
   ровно то, ради чего шкала и заведена - читался как «перенос СО СМЕНОЙ значения».

Лечение: **набор целей** (`-> row row--g4`) с покрытием по **ПОБЕДИТЕЛЮ ПО ВЕСУ**
среди названных (не «есть хоть у одной» - это дыра класса 363: элементу достаётся
то, что выиграло каскад), и **резолв `var()` ТОЛЬКО в сверке переноса**, каждая
сторона по СВОЕМУ `:root`. Глобальный резолв зажёг бы сотню потребителей при
правке одного токена; правку токена перенос не маскирует - у него свой ключ с 360.

★ЦЕНА, замеренная на живом коде: три исключения на `.chat-composer__hint`
заменяются ОДНИМ маркером `-> row row--g4` («объявлений 3, из них 1 сошлись через
токен»). До этого зона 1 объявила **117 `visual-diff-exempt`** вместо переносов -
то есть ярус 2 подтвердил, что изменения ОБЪЯВЛЕНЫ, а не что раскладка ДОЕХАЛА.
Исключение - непроверяемое молчание с прозой рядом; перенос - проверяемое
утверждение. Замена одного другим тихо выключает ярус.

★★TRIP-366 в том же PR: ключ `visual-diff-exempt` разбирается **СПРАВА НАЛЕВО**
(свойство - последняя лексема, перед ним опц. `{@media}`, остальное - единица).
Слева направо `h1 em color` неразрешима в принципе. Отсюда причина после «—»
стала ОБЯЗАТЕЛЬНОЙ - ею кончается ключ; это не новый синтаксис, её носили все 271
живой маркер в `src`.

★★★ГЛАВНОЕ И НЕПРИЯТНОЕ: **эта же правка ОТКРЫЛА дыру ровно того класса, который
чинила**. Разбор справа налево принимает любую многолексемную единицу, а `unitOf`
у единицы с классами берёт ПЕРВЫЙ класс - значит `visual-diff-exempt:
.pro-up--inline .pu-body color` молча гасил бы правку на ПРЕДКЕ, общем классе (на
`dev` такой маркер падал кодом 2). Нашёл `code-simplifier` ПРОГОНОМ - четвёртый
подряд дефект от него, а не от тестов. Правило, снимающее весь класс: **единица =
то, что гард НАПЕЧАТАЛ**; у правила с классами он печатает по ОДНОМУ классу, у
бесклассового - весь селектор → многолексемная единица законна ровно без классов.
Предикат «пробел + класс», а не «пробел»: мутация «запрет по пробелу» валит 3
теста, включая тот самый `h1 em color`, ради которого всё делалось.

★Тест «победитель по весу» с первой пробы был **зелёным при сломанном гарде**:
фикстура `.row` + `.row.row--g3`, а составное правило заводит ключ и на `.row`,
поэтому «первая попавшаяся цель» тоже давала 99px, и мутацию тест не ловил.
Разведён на две независимые единицы. Вывод прежний и снова подтверждённый: тест
проверяется мутацией, а не тем, что он зелёный.

★★Побочно найдено и починено здесь же, и это дефект того же класса, что весь
раздел: в ЭТОТ файл сутки назад (`78f199c`, память TRIP-360) попал **литеральный
байт NUL** - им записали разделитель ключа вместо слова «NUL». GNU grep из-за
одного такого байта считает файл ДВОИЧНЫМ и молча пропускает его ЦЕЛИКОМ:
`grep -rl "visual-diff-move" memory/` не показывал главный файл про 2p, а
`tail`/`cat` печатали текст как обычно. Знание физически лежало в репо и было
недостижимо тем инструментом, которым его ищут. Проявилось не в теории: разведка
в этой же сессии перечисляла файлы с маркерами и этот пропустила. Вывод: **новый
абзац памяти проверять грепом по нему же, а не глазами**, и управляющий байт в
текст не писать - писать его имя.

★Границы названы в шапке: ASCII-дефис разделителем режет ключ по ПЕРВОМУ
вхождению → единица, содержащая ` - ` (`[data-x=a - b]`), становится
необъявляемой (в `src` таких ноль); у ПРОИГРАВШЕЙ цели новое объявление переносом
не гасится; проза английскими словами после списка целей уедет в цели (гард
скажет поимённо); `var()` в кавычках развернётся, хотя CSS его не подставляет.

★Отдельно, из ревизии описания задачи своим прогоном: **маркеры 2p/2o/2m живут
РОВНО ОДИН PR** - все читаются из ДОБАВЛЕННЫХ строк диффа, и рабочее дерево тут
второй ИСТОЧНИК ДИФФА, а не «файл». Прогон 2p на чистом дереве (`dev` vs `dev`)
не упоминает ни один из 271 маркера в `src`. Накапливаются только построчные,

`orphan-exempt` (1). Значит «сколько обходов накопилось» считается по этим трём, а
271 строка `visual-diff-exempt` в `src` - инертный текст, который ЧИТАЕТСЯ как
активное подавление (117 из них - один PR #707).
