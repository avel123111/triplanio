Ключ = `единица + @media + состояние + свойство` (media/состояние — ЧАСТЬ ключа). Перенос элемента на другой класс объявляй `/* visual-diff-move: <класс|селектор> -> <цель> */` (сверяет, что объявления есть на цели с теми же значениями в том же @media/состоянии). Escape: `visual-diff-exempt: <класс|селектор> [{@media …}] <свойство> — причина` (@media — часть маркера). Неразобранный маркер = код 2. Детали/грабли: [[triplanio-ci-guard-is-code]].
- Оси канон-объекта: `npm run check:axes` (CI guard 2q, TRIP-364) — у канон-семьи в `catalog.json` объявлены **оси**; три сверки: A класс `.<семья>--<хвост>` в CSS = значение оси либо в `apart`; B каждое значение существует правилом, класс под ДЕФОЛТ существовать НЕ должен; C литерал `<семья>--<хвост>` в разметке = значение оси. Вход добровольный поштучно (сегодня `row/col/grid`). Маркера-обхода нет — обход это строка каталога. Сверка C видит только литералы (не `` `btn--${x}` ``). Детали: [[triplanio-design-system-work-rules]].
- Слой называет свой уровень: `npm run check:layers` (CI guard 2af, TRIP-466) — полноразмерная абсолютная подложка (`position:absolute` + `inset`/четыре стороны) обязана объявить `z-index`. **`position: relative` НЕ создаёт стековый контекст**, поэтому слой без уровня объявлен в ЧУЖОМ контексте выше по дереву и на мобильном движке всплывает над кадром, как только тот промоутит его в композитный слой (`<img>` в scroll-snap-ленте внутри шита с `transform`) — так обложка накрыла скрим, стрелки и НАЗВАНИЕ ТРИПА на iOS, при том что десктоп рисовал верно. Вторая половина инварианта — **кадр с оверлеями обязан быть их стековым КОРНЕМ (`isolation: isolate`)** — машинно не проверяется (кадр = свойство дерева, а не CSS) и держится этим правилом. **Уровень объявляет КАДР, а не общий примитив:** соседи у примитива в каждом вызывателе свои, и пин на нём чинит один экран и ломает другой (замер TRIP-466: `.cover__img{z-index:0}` в WebKit поднял фото над `::after`-накладкой `.nextcard`, в Chromium — нет). Храповик по изменённым файлам (`src/` + `public/`), escape `/* layer-exempt: <класс> — причина */`. Детали: [[triplanio-stacking-layers-contract]].
- Репортёр обходов: `npm run report:exemptions` (НЕ гард, не блокирует) — печатает ДВА числа: потрачено в этом PR (`floor-exempt`/`prefix-exempt`/`visual-diff-exempt`/`visual-diff-move`, живут 1 PR) и накоплено в дереве (`inline-style-exempt`/`design-token-exempt`/`orphan-exempt`, построчные). Смысл: сумму законных обходов не печатал никто, а десять за десять PR растворяют гейт.

Зелёный тест ничего не значит, пока не увидел его КРАСНЫМ (сломай счёт мутацией и перепрогони). Большинство гардов теста не имеют — добавляй, когда трогаешь. ## Hard rules (project conventions — do not violate)
1. **Analyze before code.** For any change: read the relevant base44 files + full dependency chain, check the redesign screen, write a plan, get Pavel's approval — *then* code. No guessing logic not found in code.
2. **Definition of Done = three axes:** (a) visual from the new design system (`src/design/index.jsx`: ModalHost, Dialog, Btn, Badge, Card, Avatar, EmptyState, Field…), zero leftover base44/shadcn `@/components/ui/*`; (b) functionality fully mirrors the base44 logic (validations, rules, side-effects); (c) **reuse audit passed** (rule 6).
3. **No docs on the repo.** Only codebase files here. Task specs / mockups / reports / design files live in the `Triplanio docs` and `Triplanio design new` folders. Knowledge base = the `memory/` folder + Notion. The `memory/MEMORY.md` index is **auto-imported** into every session (see the “Memory” block above) — you already have it; just open specific `memory/*.md` topic files as needed.
4. **i18n:** never hardcode UI strings — go through `t()` (en/es/ru). Bot text comes from edge functions. **Dedup keys:** each key must live in ONE locale namespace file. A key defined in two files (e.g. `trip.js` + `ai_plan.js`) is a bug — the last spread in `locales/<lang>/index.js` silently wins and the other copy is dead/conflicting. When you touch a screen's strings, grep the key across all locale files (en/es/ru), collapse duplicates to the canonical namespace, and flag what you found.
5. **Git — ВСЕГДА заканчивай PR'ом, не голым пушем.** Stage one path per line (pasting multi-path `git add` breaks in the terminal). End **every** change by: stage → commit → push the working branch → **open or update a Pull Request into `dev`** (`gh pr create` / `gh pr edit`). Это относится к ЛЮБОМУ изменению, включая docs/`memory/` — не только код. **Никогда не завершай работу на `git push` без PR:** PR — это то, что привязывает работу к Linear-задаче (по `TRIP-NN` в имени ветки) и запускает CI-гейт; пуш без PR **невидим в Linear и проходит мимо ревью**. Агент сам **не мёрджит** — мердж (особенно в `main`) делает Pavel. Если изменение тривиальное (заметка в память) — это всё равно PR, а не исключение.
6. **Reuse-first (unification gate) — BLOCKING, run before you say "done".** Default to the system that already exists; never create anything that duplicates what's already in the repo. Before finishing ANY change: grep for an existing component / CSS class / style rule / design token / breakpoint / hook / layout pattern and **reuse it**. Bind to the design system (`src/design/index.jsx`), existing tokens, existing breakpoints, existing components. Introduce something new ONLY when no existing equivalent fits — and state in your reply which existing ones you checked and why each is unsuitable ("faster to write a new one" is not a reason). Never add a second breakpoint/token/class/component that overlaps an existing one — align to what the adjacent code already uses. Collapse any duplicate you (or prior code) created; flag dead/duplicate code you spot, even if unrelated. End UI work with one line: `Reuse audit: reused …; new: none | <name + justification>`. If you can't write that line truthfully, you're not done. **Approval gate for anything new:** introducing a NEW design token, CSS class, shared component, breakpoint, switch/stepper/button, or any custom element requires Pavel's explicit approval FIRST — propose it in the plan and wait. Justification alone is not enough; do not add it unilaterally. The default is always "reuse the existing element with an adaptive variant," never "write a new one." **A new CSS class-name prefix is a new NAMESPACE — the heaviest "new" there is (TRIP-321: ~300 namespaces re-declaring the same dozen shapes is the root of the style zoo).** CI guard 2m (`scripts/ci/check-css-prefixes.mjs`) enforces the mechanical half: a prefix that exists nowhere on the base branch fails the PR; an approved new family ships with `/* prefix-exempt: <prefix> — причина + апрув */` in the same PR, so the approval is visible in the diff. Extending an existing family, deleting families and moving them between files are all free — the guard never blocks the TRIP-321 clean-up direction.
   - **A repeated inline style next to an existing class is EVIDENCE THE CLASS IS BROKEN — a workaround, never a pattern to copy (TRIP-282).** When call sites hand-write the declarations an existing class should own (`style={{ border: 'none', padding: 0 }}`, a button reset, a tile tint), reuse the CLASS and move the repeat INTO it as one element- or context-scoped rule (`button.x { … }`; or give the class the dominant value as its DEFAULT and let the exceptions override, as `.acct-ic-tile` does with its brand tint). Prefer a rule keyed on what the element IS over one keyed on where it sits in the tree: `.card > .x:only-child` looks tidy and then needs a hand-written exception the moment a sibling appears — which is another inline, i.e. the thing you were removing. Copying a neighbour's inline is not reuse — it mints a duplicate that forks the element the moment either copy is touched. Adding a rule to an EXISTING class is not "something new" and needs no approval; a new class NAME does. Corollary: **"same class" ≠ "looks the same"** — add the paddings up by hand (`.card` + the row's own) and **look at the rendered section, not at your diff**, before saying done. "The route is behind a login" is NOT a reason to skip visual verification: geometry is pure CSS — see the screenshot recipe in `memory/triplanio-visual-check-playwright.md` and `memory/feedback-look-at-the-whole-section-after-editing.md`. The mechanical half is enforced by CI guard 2l (`scripts/ci/check-inline-styles.mjs`): per-file inline-style counts are a ratchet that can only go down.
   - **Ponytail ladder (TRIP-218) — the named procedure for THIS rule, mandatory on every coding task.** Before writing code, walk the ladder and stop at the first rung that holds: (1) does this need to exist at all? (YAGNI) → (2) already in this codebase? reuse it → (3) stdlib does it? → (4) native platform feature (CSS over JS, DB constraint over app code, `<input type=…>` over a lib)? → (5) already-installed dependency? never add a new one for what a few lines do → (6) can it be one line? → (7) only then the minimum code that works. Deletion over addition; shortest **correct** diff wins, but only *after* you understand the flow end-to-end (grep every caller — bug fix = root cause, not symptom). Mark deliberate shortcuts with a `// ponytail:` comment naming the ceiling + upgrade path. Never lazy on: input validation at trust boundaries, error handling that prevents data loss, security, accessibility, or explicitly-requested behaviour. This is **not** a second source of truth — it is the step-by-step form of this reuse-first gate and the `code-simplifier` pass (rule #14); when they conflict, rules #6/#9 and the approval gate win. Vendored callable skills (read the `SKILL.md` if not surfaced): `ponytail` (full ladder + `lite`/`ultra` intensities), `ponytail-review` (review a diff for over-engineering), `ponytail-audit` (repo-wide bloat scan), `ponytail-debt` (harvest `ponytail:` shortcut comments into a ledger). Source-of-truth stays `src/design/index.jsx` + existing tokens/components.
   - **Code graph (`/graph`) — the fast way to walk rung (2) of the ladder ("already in this codebase? reuse it").** At the start of any task touching unfamiliar code, and BEFORE creating any component / hook / util, run `/graph` (local tree-sitter index of the whole repo, ~10 s, zero LLM tokens) and ask it: `graphify explain "<Name>"` = who already uses this, `graphify affected "<Symbol>"` = what a change breaks, with `file:line`. Its file-level import counts match grep exactly (`Btn` 35/35, `Badge` 11/11, `Skeleton` 15/15, `Field` 5/5, `EmptyState` 10/10 — every mismatch found during verification turned out to be the grep's error, not the graph's) and only 0.7% of edges are `INFERRED`, so the answer is citable in your `Reuse audit:` line — and the `affected` list IS the regression area you must check before saying "done". **The graph is NOT an authority on dead code.** It does not see string-dispatched calls (`invokeFn('…')`, `.rpc('…')`), JSX used inside its own file, CSS classes or i18n keys: measured on this repo — 199 false "orphan" symbols in `src/**` (all sampled ones alive) and 43 of 45 edge functions falsely orphaned. One silent-wrong-answer to know: on an ambiguous name (`Dialog` exists in both `design/` and `components/ui/`) `affected` prints an EMPTY list with no warning while `explain` honestly says `Ambiguous: … matches 2 nodes` — so an empty `affected` result means "check the name", never "nobody uses it". The graph yields a CANDIDATE; deleting anything requires a manual pass over all six reference sources — `src/**`, `supabase/functions/**`, `supabase/migrations/**`, `src/lib/i18n/locales/**`, `*.css`, n8n workflows. The cost of skipping that pass is on record: `memory/feedback-dead-i18n-key-sweep-must-scan-backend.md`. Install + full trust boundaries: `.claude/skills/graphify/SKILL.md`. Artefacts land in gitignored `graphify-out/` and are **never** committed — a stale map is worse than none, because the agent believes it.

12. **Deploy topology**
- **АГЕНТ НИКОГДА не деплоит бэкенд сам и НЕ предлагает Pavel'у задеплоить вручную.** Любой деплой (функции И миграции) идёт ТОЛЬКО через CI/CD: закоммить → PR → мердж в `dev` (затем `dev`→`main`) → GitHub Actions катит сам. НЕ вызывай MCP `apply_migration`/`deploy_edge_function`, CLI или Management API для наката в `dev`/`prod`; НЕ пиши «выполни эту команду руками». Финальная цель достигнута: функции и миграции деплоятся через один CI/CD одинаково. (Разовый bootstrap-reconcile TRIP-68 был осознанным исключением и завершён.)
- **Frontend:** Vercel, auto on push. **The agent pushes ONLY to its own working branch.** `dev` and `main` are touched **only with Pavel's explicit per-change approval** — never push, merge, or fast-forward into `dev`/`main` on your own initiative (standing rules do NOT pre-authorize it).
- **Supabase edge functions — AUTO-DEPLOY via GitHub Actions** (TRIP-73, live since 2026-06-25). Merge → `dev` deploys all functions to Supabase **dev** (`nydhzevdizkfaxdlikgc`); merge → `main` deploys to **prod** (`tizscxrpuopobgcxbekf`). Workflow `.github/workflows/supabase-deploy.yml` fires on push to dev/main when `supabase/functions/**` or `supabase/config.toml` change (+ manual `workflow_dispatch`). Deploy is **config-driven**: `supabase functions deploy --project-ref <ref>` (no slug → all functions), `verify_jwt` taken **only from `supabase/config.toml`** (never `--no-verify-jwt`). A final CI step asserts the pinned-false set via the Management API and fails on drift. **So the normal way to ship a function change is merge to `dev` (then `dev`→`main`) — not a hand deploy.** Each branch deploys its own target, so dev+prod stay in sync.
- **Supabase миграции — AUTO-DEPLOY via GitHub Actions** (TRIP-68 Ф3, с 2026-06-25, после reconcile истории). Тот же воркфлоу `supabase-deploy.yml`, job `migrate`: merge→`dev` → `supabase db push` в Supabase **dev**; merge→`main` → в **prod**; триггер по `supabase/migrations/**`. История схлопнута в единый baseline `supabase/migrations/20260625120000_baseline.sql`; репо↔dev↔prod журналы идентичны (1 запись). **Новые миграции — ТОЛЬКО `supabase migration new <name>` (таймстамп-имя `<YYYYMMDDHHMMSS>_*.sql`); нумерация `00NN` ЗАПРЕЩЕНА** — именно она порождала дрейф TRIP-68, а дубли версий ломают `db push`. Один логический change = один файл. `db push` катит только файлы новее журнала проекта. Требует секреты `SUPABASE_DB_URL_DEV`/`SUPABASE_DB_URL_PROD` (полный Postgres URI на проект).
- **Ручной деплой = АВАРИЙНЫЙ фолбэк, делает ТОЛЬКО человек (Pavel)**, не агент (хотфикс без мерджа). Должен совпадать с `config.toml` + веткой (no repo-vs-runtime drift); после — прогнать авто-деплой (`workflow_dispatch`), чтобы runtime == git.
